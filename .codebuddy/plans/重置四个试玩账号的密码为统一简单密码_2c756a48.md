## 用户需求

用户已确认：**把 father / mother / sister / brother 四个家庭成员账号的密码统一重置为一个简单的密码**，以便在本地电脑上立刻打开浏览器试玩这套家庭麻将（四个账号各开一个窗口凑一桌）。

## 补充与澄清

- 密码由我选定（用户未指定），取 **`888888`**：满足后端 `min_length=6` 的校验、纯数字易输入、适合家人轮流试玩。
- 现有账号（`backend/mahjong.db`）：

| 用户名 | 昵称 | 角色 | 处置 |
| --- | --- | --- | --- |
| `father` | 爸爸 | member | 重置 |
| `mother` | 妈妈 | member | 重置 |
| `sister` | 姐姐 | member | 重置 |
| `brother` | 弟弟 | member | 重置 |
| `admin` | 管理员 | admin | 建议一并重置（原密码同样未知，不重置则"成员管理"入口不可达，用户以后无法自行改密码） |


- 密码以 `scrypt$n$r$p$salt$hash` 存于 `users.password_hash`，单向不可逆，只能重置，且重置后**原有登录态（JWT）不会被踢下线**，不影响已打开的页面。
- 不新增任何永久业务代码、不改接口、不改配置；仅在本地开发库上做一次性数据修正，执行前先备份。

## 交付预期

重置完成后用户可在 **http://127.0.0.1:8000** 用任一账号登录：`father` / `888888` 等。视觉与界面无任何变化（这是纯数据操作）。同时给出试玩指引：四账号如何开四个互不干扰的窗口、如何用 `admin` 进"成员管理"改密码，以及**上线前必须换强密码**的提醒。

## 方案选择：直接改库，不走 API

`PATCH /api/users/{user_id}` 与前端 `MembersDialog.vue` 都支持管理员重置成员密码，但**调用它需要 admin 的 token，而 admin 密码恰恰也是未知的**——用 API 就得先重置 admin，再拿 token 批量改，绕一圈还多出两次网络依赖。因此直接用项目自带的 `hash_password` 写库：一次事务、零依赖，且仍然复用与登录校验完全一致的哈希实现，不会出现"存进去验不过"的偏差。

## 实施要点

1. **先备份**：SQLite 处于 WAL 模式，直接复制主库文件可能拿到不一致副本，必须用 `sqlite3.Connection.backup()`（Python 标准库）导出一份 `backend/mahjong.db.bak-<时间戳>`。重置是数据变更，备份是唯一回退路径。
2. **复用 `hash_password`**：`from app.core.security import hash_password`，按 `users.username in (...)` 批量赋值 `password_hash`，单次 `commit`。不要手写 scrypt，参数（n=2^14, r=8, p=1, dklen=32）必须与 `verify_password` 一致。
3. **在 `backend/` 目录、用 venv 解释器执行**：`DATABASE_URL` 是相对路径 `sqlite:///./mahjong.db`，工作目录错了会操作到另一个空库。脚本用 PowerShell here-string 管道喂给 `python -`，执行完不留临时文件。
4. **双段验证**：

- 数据层：对每条新哈希跑 `verify_password("888888", h)`，必须全为 `True`；
- 接口层：`POST /api/auth/login` 用新密码登录 5 个账号，期望 200 并返回 token；旧密码期望 401。

5. **浏览器层验证**：用 `[skill:playwright-cli]` 真实浏览器依次登录 `father / mother / sister / brother`，确认进入大厅而非停在登录页，截图留证——这是"能不能试玩"的最终判据，比接口 200 更贴近用户实际体验。
6. **并发安全**：后端进程正在运行并持有 WAL 连接，另一进程短事务写入是安全的；若要绝对稳妥，可在写库前停服务、写完再起，但当前规模没有必要。

## 风险与边界

- 弱口令 `888888` 只适用于本机试玩；`docs/部署.md` 的上线流程里必须改成强密码，否则公网可被撞库。
- 只改 5 条 `password_hash`，不动 `display_name` / `role` / `is_active` / `color`，不触碰 `rooms` / `games` / 战绩数据。
- 若用户事后想改回，从备份文件恢复即可（`mahjong.db.bak-*`），恢复时需同时删除 `-wal` / `-shm` 边车文件。

## 执行产物

一个带时间戳的数据库备份、5 条被重置的 `password_hash`、接口与浏览器两层验证结果、一段可直接照做的试玩指引。
