# 运维与备份

## 1. 日常巡检

| 项 | 命令 / 位置 | 期望 |
| --- | --- | --- |
| 服务状态 | `systemctl status mahjong --no-pager` | `active (running)` |
| 健康检查 | `curl -s https://<host>/majiangapi/health` | `{"ok":true,...}` |
| 最近错误 | `journalctl -u mahjong -p err -n 100 --no-pager` | 无持续报错 |
| Nginx | `nginx -t`、`tail -n 100 /var/log/nginx/error.log` | 无 502/504 |
| MySQL | `systemctl status mysql`、`mysqladmin -u root -p ping` | `mysqld is alive` |
| 磁盘 | `df -h /`、`du -sh /data/majiang/log /data/majiang/data /data/webserver/majiangapp/tiles` | 使用率 < 80% |
| 连接数 | `SHOW STATUS LIKE 'Threads_connected';` | 远小于 `max_connections` |
| 慢查询 | `SHOW VARIABLES LIKE 'slow_query_log';`、慢日志 | 无 > 1s 的常态查询 |

健康检查已自动化：`monitor/restore_monitor.sh` 每 5 分钟探一次本机 `http://127.0.0.1:8000/api/health`（不经 Nginx），异常直接重启应用并写 `monitor.log`；上表为人工巡检补充项（磁盘、慢查询、连接数不在 monitor 能力范围内）。

## 2. 备份

### 2.1 备份内容

| 内容 | 路径 | 说明 |
| --- | --- | --- |
| 数据库 | `mysqldump` 产物 | 结构 + 数据，含 `mj_schema_version` |
| 上传文件 | `/data/webserver/majiangapp/tiles/` | 皮肤图片（`UPLOAD_DIR`） |
| 配置 | `/data/majiang/src/.env`（加密存放） | 含口令，不入普通备份包 |
| 代码版本 | git tag | 可重建 |

### 2.2 全量备份任务

备份由 `code/backend/src/schedule/dataBackup.py` 承担，crontab 在 03:00 拉起 `restore_backup.sh`（唯一入口，不再单独维护 `backup.sh`）：

| 步骤 | 产物 | 说明 |
| --- | --- | --- |
| mysqldump | `mahjong-db-YYYYmmdd-HHMMSS.sql.gz` | `--single-transaction --routines --triggers`，口令经 `MYSQL_PWD` 传入，不出现在命令行与日志 |
| 上传文件 | `uploads-YYYYmmdd-HHMMSS.tar.gz` | 只打包 `UPLOAD_DIR/tiles/`（`/data/webserver/majiangapp/tiles`）；同目录下的前端构建产物不进备份 |
| 校验 | `checksum-YYYYmmdd-HHMMSS.txt` | 逐文件 sha256 |
| 自检 | — | `gzip` 可解压、文件非空；失败退出非 0 供 `MAILTO` 告警 |
| 清理 | — | 删除 14 天前的三类文件（`BACKUP_KEEP_DAYS` 可调） |

crontab 见 `code/backend/src/schedule/crontab.txt`；备份在 03:00、清理在 04:00，**顺序不可调换**：删除动作永远有当天快照兜底。备份产物默认写 `BACKUP_DIR`，生产指向 `/data/majiang/data/backup`。

备份账号只需 `SELECT, LOCK TABLES, SHOW VIEW, EVENT, TRIGGER`。

手工补跑：

```bash
cd /data/majiang/src
sh schedule/restore_backup.sh                 # 全量
sh schedule/restore_backup.sh --dry-run       # 只看命令
```

### 2.3 留存与异地

- 本地保留 14 天（脚本自动清理）；**不做月度归档**——超过 14 天的备份即不可用，这是“3 年数据保留”的执行口径。
- 如需异地容灾，每周把最新一份同步到对象存储/另一台机器（`rclone`/`ossutil`），该动作在备份主机侧脚本之外，不纳入本项目 cron。
- 备份文件权限 `600`，目录 `700`。

## 3. 恢复

### 3.1 数据库

```bash
sudo systemctl stop mahjong
mysql -u root -p -e "CREATE DATABASE mahjong_restore DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
gunzip -c /data/majiang/data/backup/mahjong-db-YYYYmmdd-HHMMSS.sql.gz | mysql -u root -p mahjong_restore
mysql -u root -p -e "SELECT versionCode, appliedYMDHMS FROM mahjong_restore.mj_schema_version ORDER BY recID DESC LIMIT 3;"
# 校验关键表
mysql -u root -p -e "SELECT COUNT(*) FROM mahjong_restore.mj_room; SELECT COUNT(*) FROM mahjong_restore.USER_BASIC;"
```

确认无误后：

```bash
sudo systemctl stop mahjong
mysql -u root -p -e "RENAME TABLE mahjong_data.mj_room TO mahjong_old.mj_room;"   # 或直接改应用库名
# 推荐做法：把 .env 的 MYSQL_*_DB 指向 mahjong_restore，重启验证，再切换回原库名
sudo systemctl start mahjong
```

### 3.2 上传文件

```bash
sudo systemctl stop mahjong
# 包内只有 tiles/ 一层, 直接解到站点目录下的 majiangapp, 不碰前端构建产物
sudo tar -xzf /data/majiang/data/backup/uploads-YYYYmmdd-HHMMSS.tar.gz -C /data/webserver/majiangapp
sudo chown -R majiang:majiang /data/webserver/majiangapp/tiles
sudo systemctl start mahjong
```

### 3.3 恢复演练（每季度）

1. 在测试机建空库 `mahjong_restore`。
2. 导入最新备份与上传包。
3. 起服务，登录 → 看战绩 → 打开牌桌 → 切换皮肤。
4. 记录耗时与问题；演练不影响生产。

## 4. 日志

| 日志 | 位置 | 保留 |
| --- | --- | --- |
| 应用日志 | `/data/majiang/log/mahjong.log`（10MB × 5 滚动） | 同时输出 stdout，`journalctl -u mahjong` 可查 |
| Nginx access/error | `/var/log/nginx/` | logrotate 默认 14 天 |
| MySQL 慢查询 | `/var/log/mysql/slow.log` | 14 天 |

## 5. 常见故障

| 现象 | 排查 | 处理 |
| --- | --- | --- |
| 502 Bad Gateway | `systemctl status mahjong`、`journalctl -u mahjong -n 200` | 修复启动错误；确认 8000 监听 |
| WSS 握手失败 | Nginx `Upgrade/Connection` 头、`proxy_read_timeout` | 按部署文档配置；确认证书有效 |
| 登录 503 | `curl $ACCOUNT_SERVICE_URL` | 修复账号服务/网络；必要时临时只读 |
| 登录 401 | JWT 过期、`SECRET_KEY` 变更 | 重新登录；`SECRET_KEY` 变更会使全部会话失效 |
| 页面空白 | `/majiangapp/assets/*` 404 | 在 `/data/majiang/build/frontend` 重新 `npm run build` 并 `rsync dist/ /data/webserver/majiangapp/`；确认 `vite base=/majiangapp/` 与 `location /majiangapp/` 的 `root /data/webserver` |
| 图片 404 | `/majiangapp/tiles/` 指向、`/data/webserver/majiangapp/tiles` 权限 | 检查 `location /majiangapp/tiles/` 的 `root /data/webserver`、DB 中 `fileID` 相对路径、`majiang` 与 nginx worker 可读 |
| 房间突然消失 | 服务重启、房间已关闭 | 查 `mj_game` 是否 `ABORTED`；正常现象 |
| 写入报 3140 | JSON 列传了空串 | 走 `normalizeJsonValue4DB`；修数据 |
| 连接池耗尽 | `Threads_connected`、慢查询 | 临时调大 `MYSQL_POOL_MAX`；查长事务 |
| 磁盘写满 | `df -h`、`du -sh /data/webserver/majiangapp/tiles /data/majiang/log /data/majiang/data` | 清理旧备份/孤儿图片；扩容 |
| 清理任务报错 | `tail -n 100 /data/majiang/log/schedule/clean.log`，看 `SUMMARY failed_tags` | 按 tag 单独重跑 `--only <tag> --apply`；表名不在白名单立即查代码 |
| 应用每 5 分钟重启 | `tail /data/majiang/log/schedule/monitor.log`；查 `monitor/tempMonitorFileName.json` | 首次运行误判/`num` 配错/`host` 漏端口，见 [部署 §5.5](部署.md) |
| 备份任务失败 | `backup.log` 的 `dataBackup failed` | 查 `MYSQL_PWD`、mysqldump 权限、`BACKUP_DIR` 空间 |

## 6. 数据维护

**全部自动化，无人工归档、无月度任务。** 所有定时任务由 crontab 拉起 `restore_*.sh`，每个脚本一个 `flock`，失败以非 0 退出码交给 `MAILTO` 告警。

### 6.1 定时任务一览

| 时刻 | 脚本 | 内容 | 日志 |
| --- | --- | --- | --- |
| `0 0 * * *` | `schedule/restore_logslice.sh` | 切分前一天的 `clean/backup/monitor` 日志，保留 30 天 | `logslice.log` |
| `0 3 * * *` | `schedule/restore_backup.sh` | `mysqldump` + `uploads` 打包 + `sha256` + 自检，本地保留 14 天 | `backup.log` |
| `0 4 * * *` | `schedule/restore_clean.sh` | 到期数据物理删除（见 6.2） | `clean.log` |
| `*/5 * * * *` | `monitor/restore_monitor.sh` | 探 `/api/health`、文件变更、进程存活，异常重启 | `monitor.log` |

顺序不可调换：**先备份（03:00）再删除（04:00）**，删除永远有当天快照兜底；`logslice` 在 00:00 先把前一天的三个日志封存，避免写入与切片打架。

所有脚本共用解释器 `/data/userbin/python3/bin/python3`，由 `MAHJONG_HOME` / `MAHJONG_PYTHON` 覆盖路径，不使用项目 venv。

### 6.2 保留期与删除方式

| 数据 | 保留期 | 到期动作 | 可覆盖的 `.env` 变量 |
| --- | --- | --- | --- |
| `mj_room_message`（聊天 + 系统播报） | 180 天 | 批量物理删除；`roomStatus='OPEN'` 的房跳过 | `MESSAGE_RETENTION_DAYS` |
| `mj_game_round` / `mj_game_player` / `mj_game` | 1095 天（3 年） | 只删 `FINISHED`/`ABORTED`；按 `逐局 → 座位 → 场次` 顺序同一事务内删 | `DATA_RETENTION_DAYS` |
| `mj_room` | 与场次同期 | 只删 `CLOSED` 且无场次引用的房，排在 `games` 之后 | 同上 |
| `mj_audit_log` | 1095 天 | 批量物理删除 | 同上 |
| 家庭自定义模板/皮肤（`delFlag='1'`） | 30 天 | 删记录；资源行一并删，文件交给 `files` | `SOFT_DELETE_PURGE_DAYS` |
| `UPLOAD_DIR/tiles/**`（生产 `/data/webserver/majiangapp/tiles/`）孤儿文件 | 30 天 | DB 无引用且 `mtime` 超期即删，清空目录 | `ORPHAN_FILE_DAYS` |
| 备份文件 | 14 天 | 按文件名前缀 + mtime 清理 | `BACKUP_KEEP_DAYS` |

删除一律 `DELETE ... WHERE <时间列> < ? ORDER BY recID LIMIT 5000` 循环、每批独立事务提交，单次最多 20 批（`SCHEDULE_BATCH_SIZE` / `SCHEDULE_MAX_BATCHES`），本次删不完记 `TRUNCATED`，次日继续。**禁止逐条删除、禁止一次性大事务**：长事务会拖慢 `/api/health`，导致 monitor 在下一轮把应用误杀。

删除条件依赖 [02 §4 索引](../plan/02-数据库设计.md) 的 5 条索引（`idx_mjmsg_created`、`idx_mjgame_started`、`idx_mjgr_finished`、`idx_mjroom_closed`、`idx_mjaudit_created`），未建索引不要启用清理。

### 6.3 保护名单（脚本内硬编码，白名单外的表一律拒绝删除）

`USER_BASIC`、`mj_family`、`mj_family_member`、`mj_user_pref`、`mj_rule_family`、`mj_rule_template(familyID=0)`、`mj_tile_skin(familyID=0)`、`mj_schema_version`；以及任何 `PLAYING` 场次、`OPEN` 房间。

### 6.4 手动执行与灰度

```bash
cd /data/majiang/src
sh schedule/restore_clean.sh --dry-run                      # 只统计候选条数
sh schedule/restore_clean.sh --dry-run --only messages,files
sh schedule/restore_clean.sh --apply --only messages        # 单 tag 落地
```

- 注意 `restore_clean.sh` **无参数即 `--apply`**（cron 语义），手工排查务必显式 `--dry-run`。
- 首次上线前先跑 3–7 天 dry-run，把 `candidates` 与预期对照；`files` 的 `bytes` 应接近 `du -sh $UPLOAD_DIR/tiles` 与 DB 引用量之差。
- 清理不可恢复，回滚只有 14 天内的备份：恢复见 §3。

### 6.5 孤儿图片与软删文件

1. 引用清单来自 `mj_tile_skin_asset.fileID/thumbFileID` + `mj_tile_skin.previewFileID`，不再手工导出比对。
2. 只删「DB 无引用且 `mtime > ORPHAN_FILE_DAYS`」的文件，删空目录。
3. 软删皮肤先删记录再删文件；删除前当天的 `uploads-*.tar.gz` 已存在（03:00 备份）。
4. 文件与记录不同步时以 DB 为准，下次运行会补齐。

### 6.6 账号异常

- `USER_BASIC` 是账号服务的镜像；资料不一致时以账号服务为准，重新登录会覆盖差异字段。
- 不要手工改 `roleName` 来提权；改账号服务角色，重新登录生效。

## 7. 安全

- `.env` 权限 `600`，属主 `majiang`；不纳入 git。
- MySQL 只监听回环；应用账号最小权限。
- 上传接口仅管理员，限制 png/webp、≤512 KB、单皮肤 ≤8 MB。
- 定期 `sudo apt update && sudo apt upgrade`，关注 MySQL/Python 安全公告。
- 每季度轮换 `SECRET_KEY`（会使全部会话失效，选在无人对局时）。
