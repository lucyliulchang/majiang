规则：

- 路由不写 SQL、不写跨表事务；业务在 `processor/`。

- 表结构只改 `database/*.txt`，`auto_generated/` 由生成器覆盖。
- 日志只写 `code/backend/log`，其他运行时数据只写 `code/backend/data`；两者路径由 `code/backend/src/config/localSettings.py` 统一给出，可用 `LOG_DIR` / `DATA_DIR` 覆盖。
- 前端需要直访的图片放 `code/backend/data/webserver/majiangapp/tiles/`，URL 前缀 `/majiangapp`（本地由后端挂载，生产由 Nginx 从 `/data/webserver/majiangapp` 出）。
- 前端生产前缀 `/majiangapp/`、`/majiangapi` **尚未接入**：`vite base`、路由 base、`api/http.ts` 的 REST base 目前都是本地形态（`/`、`/api`）。上线前按 [部署 §5.3](部署.md) 的表格改完再构建。

## 3. 时间与日期处理

> **唯一参照实现**：contentHub 的 `common/miscCommon.py`
> （`D:\StevenLianData\0301. Private Project\ylwzProject\contentHub\code\src\common\miscCommon.py`，
>  P4 移植到本项目后位于 `code/backend/src/common/miscCommon.py`）。
> 表侧约定见 [plan/02 §2.1](../plan/02-数据库设计.md)：时间列 `VARCHAR(16)`、值 `YYYYMMDDHHMMSS`、Asia/Shanghai、字段名以 `YMDHMS` 结尾。
> 两处必须一致：**库里存什么、代码里算什么，都用同一套字符串格式**，不做时区换算，不存时间戳。

### 3.1 三条硬规则

1. **时间是定长字符串**：`YMDHMS = YYYYMMDDHHMMSS`（14 位）；纯日期用 `YMD = YYYYMMDD`（8 位）。不入库 float 秒、不入库带时区的 `datetime`。
2. **一律本地时间**：`time.localtime()` / `datetime.now()`。服务器时区固定 `Asia/Shanghai`（部署时 `timedatectl` 设置并校验，见 [部署 §5.5](部署.md)）。业务时间**不用** `utcnow()`；唯一例外是 JWT 的 `exp/iat`，那是协议标准要求 UTC。
3. **秒级精度**：毫秒只出现在日志与耗时统计（`getTimeStamp()` / `getHumanTimeStamp()`），不落库、不进接口。

### 3.2 函数速查（照抄 miscCommon，不许自造）

| 用途 | 函数 | 输入 → 输出 |
| --- | --- | --- |
| 当前时间 | `getTime()` | → `20261027193005` |
| 小时桶（日志切片） | `getHour()` | → `2026102719` |
| 秒差 | `diffTime(t1, t2)` | `YMDHMS, YMDHMS` → 整数秒（`t2 - t1`） |
| 天差 | `diffDays(t1, t2)` | → 整数天 |
| 加减秒 | `addTime(t, interval)` | `YMDHMS, 秒` → `YMDHMS`；秒可为负 |
| 机读 → 人读 | `humanTime(t)` / `formatTime(t)` | → `2026-10-27 19:30:05` |
| 人读 → 机读 | `humanTime2YMDHMS(t)` | → `YMDHMS`（空串进空串出） |
| 字符串 ↔ datetime | `str2Time` / `time2YMDHMS` / `YMDHMS2time` / `humanTime2Time` | 秒级互转 |
| 日期推算 | `getPassday(n)` / `getYesterday()` / `getDaysBefore(n)` / `getDaysAfter(n)` / `getDaysBeforeAfter(n)` | → `YMD` |
| 周计算 | `getCurrentWeek(mode)` / `getWeekRange(YMD, mode)` / `weekDay` 类 | `mode`：`iso`(默认)、`monday`、`sunday`、`simple`、`xls` |
| 对外时间 | `get_rfc3339_time(offset_minutes)` / `convert_to_rfc3339(t)` / `iso8601ToYMDHMS(t)` | RFC3339 `+08:00` ↔ `YMDHMS` |

`weekDay` 类：`YMDHMS` 入参 → `.wdayName/.wdayCNName`、`.easyFormat()`、`.getWeekInfo()`、`.getYearWeek()`、周活跃模式 `setWeekActive("YYYYYNN")`（索引 0 = 周一）。

### 3.3 使用纪律与坑

- **比较/排序直接用字符串**：`YMDHMS`、`YMD` 都是定长且高位在前，字典序即时间序（范围查询 `createdYMDHMS >= %s` 因此成立），不要转成 `datetime` 再比。
- **解析失败行为不一致**：`diffTime` / `diffDays` 吞异常返回 `0`（所以 `0` 不能当成"无数据"）；其余函数（`addTime`、`str2Time`、`humanTime` 等）直接抛 `ValueError`。入参必须先由上游校验格式，不要把用户输入直接喂进去。
- **周日/周一**：`time.strptime()[6]` 与 `datetime.weekday()` 都是周一 = 0；`strftime('%U')` 才是周日为首。跨年周（第 0 周）`getYearWeek()` 已归到上一年，别自己用 `%W` 判断。
- **业务时间只由应用写入**：SQL 里不写 `NOW()` / `CURDATE()`，统一在 `processor` 层用 `getTime()` 生成后传参，保证时区与格式只有一处来源。
- **对外接口用 RFC3339**：与前端、contentHub 账号服务交换时间一律 `2026-10-27T19:30:05+08:00`；入口用 `iso8601ToYMDHMS()` 收敛成 `YMDHMS`，出口用 `convert_to_rfc3339()` 或 `get_rfc3339_time()`。
- **日志目录锚定方式照抄**：`miscCommon.setLogNew()` 的默认目录由 `__file__` 推算到项目根 `log/`，不随进程 cwd 漂移（历史踩坑：相对路径在其他 cwd 下解析到不可写目录）。本项目同样在 `config/basicSettings.py`（常量与默认目录）与 `config/localSettings.py`（派生路径）里按 `BACKEND_DIR` 推算 `log_dir`，新代码不要写相对路径。

### 3.4 本仓库现状（P4 移除 ORM 前）

现 SQLite 版仍是 ORM `DateTime` + UTC，P4 换 MySQL 时按上表统一替换：

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| `db/models.py` 的 `utcnow()` | `datetime.now(timezone.utc)` | 删除；写库字段由 processor 传 `getTime()` |
| `realtime/persist.py` | `utcnow()` | `getTime()` |
| `main/api/auth.py` `/api/auth/server-time` | `datetime.now(timezone.utc).isoformat()` | `get_rfc3339_time()` |
| `common/securityCommon.py` JWT `exp/iat` | UTC | **保持 UTC**（协议标准，不改造） |
| `schedule/dataClean.py` 的 `getNowYMDHMS` / `getLimitYMDHMS` | 本地重复实现 | 换成 `miscCommon` 函数族，删掉本地副本 |

新代码从今天起不要再新增 `datetime.now()` / `utcnow()` 自造时间；迁移期如需临时保持 ORM，也只在 `db/models.py` 一处出现。

## 5. 表结构变更流程

> 唯一来源是 `database/*.txt`；禁止手写 DDL 改库、禁止手改 `auto_generated/`。

1. **改定义**：编辑 `database/mj_xxx.txt`（单空格、无 Tab、`COMMENT` 不含 `%`/`#`、首列 `recID INT`、尾部七字段）。
2. **同步文档**：先更新 [`plan/02-数据库设计.md`](../plan/02-数据库设计.md) 的字段表。
3. **生成**（必须在 `database/` 目录、传裸文件名）：

   ```powershell
   cd code/backend/src/database
   python mysqlCodeGenerator.py -i mj_xxx.txt -t xxx
   ```

4. **合并**：

   ```powershell
   cd code/backend/src
   python tools/mergeMysqlCommon.py
   ```

5. **改表**：测试库先演练，再生产；只允许 `ALTER`，变更前后各做一次备份。
6. **写版本**：向 `mj_schema_version` 追加一行（如 `20261101_01`）。
7. **补查询**：在 `mysqlCommon.py` 手写区新增/调整 `query_mj_xxx_*`，JSON 列登记 `MYSQL_JSON_COLUMN_NAME_LIST`。
8. **跑测试**：`pytest -q` + 手工验证相关端点。

生成器硬约束：不支持外键、复合唯一键、`CHECK`；唯一性用单列 `xxxKey` 拼接；生成版 `query_*` 的 LIMIT 不可用，列表查询必须手写。

## 8. 调试

| 场景 | 做法 |
| --- | --- |
| 看 SQL | `config/localSettings.py` 打开 `MYSQL_LOG_SQL=1`（仅本地），日志打印参数化 SQL 与耗时 |
| 只看接口不连库 | `MYSQL_SKIP_CONNECT=1`，用于导入检查与纯前端联调 |
| 账号服务未起 | 登录会 503；先用 `curl` 检查 `ACCOUNT_SERVICE_URL` 是否可达 |
| 注册入口消失 | `ACCOUNT_ALLOW_REGISTER=false`（生产默认） | 本地置 `true` 重启；入口由 `GET /api/auth/options` 控制，不看前端写死 |
| 收不到验证码 | 账号服务短信通道未配置，或手机号不在测试白名单 | 查 acis 日志；注册与找回共用 `A6A0`，先用 `curl` 打 `/api/auth/verify-code` 定位 |
| 找回密码 403 | `ACCOUNT_ALLOW_PASSWORD_RESET=false` | 置 `true` 重启；前端同步隐藏「忘记密码」 |
| 验证码刚发就失效 | 已被使用（一次性）或超过 10 分钟 TTL | 重新发码；本地不缓存验证码，别在 DB/Redis 里找 |
| WS 调试 | 浏览器 DevTools → Network → WS；或 `wscat -c "ws://127.0.0.1:8000/ws?token=...&code=428915"` |
| 模拟多用户 | 不同浏览器 profile 登录不同账号；不要共用 localStorage |
| 家庭隔离 | 建两个家庭、两个账号，交叉请求应全部 403 |

## 10. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 `Unknown database` | 库未建 | 执行建库 SQL |
| 启动报 `Access denied` | 口令/账号不符 | 检查 `.env`，口令只放环境变量 |
| 表名变成 `database/mj_room` | 未在 `database/` 目录执行生成器 | `cd database` 后传裸文件名重跑 |
| 中文乱码 | 连接未设 utf8mb4 或生成产物 GBK | 检查 `charset`；合并工具容错解码后统一 UTF-8 |
| 插入 JSON 报 3140 | 字符串不是合法 JSON | 走 `normalizeJsonValue4DB`，空串转 NULL |
| 写完立刻读不到 | 读写分离延迟 | 家庭规模默认同实例；如需只读库，关键读走 `dbW` |
| 登录 503 | 账号服务不可达 | 检查地址/端口/网络，或临时只读模式 |
| 房间重启后消失 | 房态在内存 | 正常现象；看战绩确认已落库 |
