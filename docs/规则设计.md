# 规则设计

规则模板是一份 JSON 配置，由后端 Pydantic `RuleConfig` 强校验（`backend/app/schemas/rule.py`）。开桌时把它快照进房间（`rooms.rule_snapshot`）与场次（`games.rule_snapshot`），此后修改模板不影响进行中与历史对局。

## 字段总览

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `base_score` | int (1-100) | 1 | 底分，每个番值折算的基数 |
| `fan_mode` | `linear` / `exponential` | `exponential` | 番数算法：线性累加，或 2 的 N 次方 |
| `fan_cap` | int (0-30) / null | 8 | 封顶番数，null 为不封顶 |
| `fan_table` | FanItem[] | 20 项 | 番种清单（见下） |
| `patterns` | PatternSwitches | 全开 | 四类牌型开关，十三不靠带子参数 |
| `allow_chow` | bool | true | 是否允许吃 |
| `turn_timeout` | `{enabled, seconds}` | `{true, 15}` | 出牌限时 |
| `kong_score` | `{enabled, exposed, hidden, added}` | `{true, 1, 2, 1}` | 杠分 |
| `ting_hint` | `{enabled, value}` | `{true, null}` | 听牌提示（只用 `enabled`） |
| `draw_penalty` | `{enabled, value}` | `{false, 0}` | 荒庄罚分：每家罚 N 分给庄家 |
| `discard_pay_mode` | `single` / `all` | `single` | 点炮怎么付：放炮的一家独付，或三家分摊 |
| `dealer_continue_on_win` | bool | true | 庄家胡牌连庄 |
| `dealer_continue_on_draw` | bool | true | 荒庄连庄 |
| `rounds_per_game` | int (1-32) | 4 | 一场打几局 |
| `claim_window_seconds` | int (3-30) | 8 | 碰杠胡询问窗口时长 |

## 三组「开关 + 从属配置」

出牌超时、杠分、听牌提示在语义上都是"可选能力 + 参数"，因此统一建模为嵌套对象 + `enabled` 标志。**禁止用 `0` / `null` / `-1` 表达"未启用"** —— 那会让校验、界面禁用态、结算取值三处各自猜测语义。

三条纪律，任何新增可选规则项都必须同时满足：

1. **校验**：`enabled=true` 时才校验从属值范围；`enabled=false` 时既不校验也不取用，但**保留原值**，方便来回切开关不丢已填数字。
2. **取值**：结算器与快照生成器必须先判 `enabled` 再读分值，禁止直接读 `kong_score.exposed` 参与运算，否则关掉开关后会静默加分。
3. **下发**：关闭时服务端不下发对应字段，前端连控件/角标都不渲染。

### 出牌超时 `turn_timeout`

- `enabled=false`：轮到谁就无限等待，牌桌顶部标"不限时"，底部提示「本局不限时，慢慢打」，快照里 `deadline` 恒为 `null`。
- `enabled=true`：`seconds` 范围 10-120（默认 15），到点由服务端代打一张。
- **与 claim 窗口无关**：碰杠胡询问窗口（默认 8 秒）是防"迟迟不响应"的保护机制，永远开启，不随该开关关闭。

### 杠分 `kong_score`

- `enabled=false`：**杠牌照常可以进行**（引擎不拦截吃碰杠合法性），只是三类杠分全按 0 结算，结算面板不出现杠分行，聊天里仍记"杠"。
- `enabled=true`：`exposed` / `hidden` / `added` 三个分值范围 0-20。
- 若日后要"只给暗杠计分"，把三个字段各自升级为 `ToggleValue` 即可，引擎接口不变。

### 听牌提示 `ting_hint`

- `enabled=false`：轮到自己时不做 34 次判胡，快照中 `tenpai` 为空对象，前端不渲染"N 张牌可听"角标。
- `enabled=true`：`phase=discard` 且轮到自己时，快照下发 `tenpai: {"<tile>": [等待的牌...]}`。

## 番种表 `fan_table`

每一项：

```json
{ "id": "qing_yi_se", "name": "清一色", "fan": 6, "exclusive_group": "suit", "stackable": false }
```

- `id`：小写字母/数字/下划线（≤32 字符），唯一
- `fan`：0-100
- `exclusive_group`：互斥组名（可为空）。**同一组内只取番值最高的一项**，例如 `suit` 组的清一色 6 番会顶掉混一色 2 番
- `stackable`：是否允许多次累加（如"杠"每杠一次加一次）

求值流程：牌型插件产出候选番种 → 按互斥组去重 → 校验前置条件 → 汇总总番 → 按 `fan_mode` 与 `fan_cap` 折算。

## 牌型开关 `patterns`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `standard` | true | 标准胡：4 面子 + 1 将，递归拆解、多解取最大番 |
| `seven_pairs` | true | 七对（含龙七对判定） |
| `thirteen_orphans` | true | 十三幺 |
| `thirteen_unrelated` | 关闭 | 十三不靠，带三个子参数 |

十三不靠在各地定义不一，所以做成**受参数驱动的插件**而不是写死：

| 子参数 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | false | 是否启用该牌型 |
| `require_all_honors` | false | 是否要求七星（7 种字牌齐全）→ 七星不靠 |
| `allow_pair` | true | 是否允许 1 个对子（false 为全不靠） |
| `min_gap` | 3 | 同花色数牌之间的最小间隔 |

匹配条件：门前清（无吃碰杠）、各类牌不重复、同花色数牌间隔不小于 `min_gap`、按参数决定是否必须 7 种字牌、按参数决定能否含 1 对。

## 结算折算

- `fan_mode=linear`：`分数 = base_score × max(1, 总番)`（0 番也按 1 份底分算）
- `fan_mode=exponential`：`分数 = base_score × 2^总番`（0 番即 1 倍底分），例如清一色 6 番 + 自摸 1 番 = 2^7 → 128 分
- 总番先按 `fan_cap` 截断，`breakdown` 里同时给出 `fan_raw` 与 `fan_total`，结算面板会标注"已按封顶 N 番计算"
- 自摸：三家各付；点炮：按 `discard_pay_mode` 决定放炮者独付或三家分摊
- 荒庄：`draw_penalty.enabled` 为真时每家罚 `value` 分给庄家，否则四家 0 分

## 校验与常见报错

`RuleConfig._cross_check` 会做以下跨字段校验，全部给出中文提示：

| 规则 | 报错 |
| --- | --- |
| `base_score` 在 1-100 | 底分必须在 1-100 之间 |
| `fan_cap` 为 null 或 0-30 | 封顶番数必须在 0-30 之间，留空表示不封顶 |
| `rounds_per_game` 在 1-32 | 一场局数必须在 1-32 之间 |
| `claim_window_seconds` 在 3-30 | 碰杠胡询问窗口必须在 3-30 秒之间 |
| `fan_table` 非空且 id 唯一 | 番种表不能为空 / 番种标识「x」重复 |
| 番种 `id` 匹配 `^[a-z][a-z0-9_]{0,31}$`，`fan` 在 0-100 | 番种标识/番值不合法 |
| `turn_timeout.enabled` 时 `seconds` 在 10-120 | 出牌限时必须在 10-120 秒之间 |
| `kong_score.enabled` 时三项在 0-20 | 明杠/暗杠/补杠分数必须在 0-20 之间 |
| `draw_penalty.enabled` 时罚分在 0-20 | 荒庄罚分必须在 0-20 之间 |
| 四类牌型至少开一个 | 至少要启用一种胡牌牌型，否则这局永远胡不了 |
| 十三不靠开启时 `min_gap` 在 2-9 | 十三不靠的最小间隔必须在 2-9 之间 |

开关关闭时从属值一律跳过校验（所以可以把 15 秒留着、把开关关掉，随时再打开）。保存前可调用 `POST /api/rules/validate` 拿到中文错误与摘要，前端把错误行整行高亮。
