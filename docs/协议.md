# WebSocket 协议

服务端权威：所有合法性在服务端判定，前端提交的只是"意图"。牌墙永不下发，快照逐座位生成。

## 连接

```
ws://<host>/ws?token=<JWT>&code=<6 位邀请码>
```

鉴权失败 `close(4001)` 并先发一条 `error{UNAUTHORIZED}`；房间不存在或已关闭 `close(4004)` 并先发 `error{ROOM_NOT_FOUND}`。座位已满时仍可连接，但会收到 `error{ROOM_FULL}` 并以观战身份进入。

## 信封

```json
{ "v": 1, "type": "event.discarded", "ts": 1792900000, "data": { "seat": 2, "tile": 15 } }
```

- `v`：协议版本，当前固定 `1`
- `type`：消息类型
- `ts`：服务端秒级时间戳
- `data`：载荷
- `seq`：仅客户端上行时可选，服务端下发不带 `seq`；前端用本地自增 `seq` 做去重与顺序校验

## 客户端 → 服务端

| type | data | 说明 |
| --- | --- | --- |
| `ping` | — | 心跳，服务端回 `pong` |
| `state.resync` | — | 请求全量快照（断线重连后由前端自动发起） |
| `seat.ready` | — | 准备 / 取消准备（切换语义） |
| `game.start` | — | 只有房主可开桌；需 4 人入座且全部准备 |
| `game.next` | — | 只有房主可开始下一局；本局必须已结算 |
| `game.action` | `{action, tiles?, kong_kind?}` | 牌局动作，见下 |
| `chat.send` | `{content}` | 房间聊天，1-200 字，5 秒内最多 3 条 |

### `game.action`

```json
{ "action": "discard", "tiles": [15] }
{ "action": "chow",    "tiles": [13, 14] }
{ "action": "pong",    "tiles": [15] }
{ "action": "kong",    "tiles": [15], "kong_kind": "hidden" }
{ "action": "hu" }
{ "action": "pass" }
```

- `tiles` 用 0-33 的牌编码：0-8 万、9-17 筒、18-26 条、27-30 东南西北、31-33 中发白
- `kong_kind`：`exposed`（明杠）/ `hidden`（暗杠）/ `added`（补杠）
- 动作幂等：重复提交同一动作返回当前状态而不是报错，可安全重试

## 服务端 → 客户端

### 会话类

| type | data |
| --- | --- |
| `room.welcome` | `{room:{code,name,host_id,rule_name,rule_brief}, self_seat, chat:[...]}`，连接建立即下发，`chat` 为最近 50 条历史消息 |
| `state.snapshot` | 全量快照，见下 |
| `chat.message` | `{id, room_id, user_id, user_name, kind, content, created_at}`，`user_id` 为 null 表示系统播报 |
| `error` | `{code, message}`，message 为可直接展示的中文 |
| `pong` | — |

### 事件类（增量）

| type | data |
| --- | --- |
| `event.ready_changed` | `{seat, ready}` |
| `event.round_started` | `{round_no, dealer_seat, round_wind, wall_count}` |
| `event.drawn` | `{seat, wall_count}`，只广播摸牌这件事，不泄露是哪张 |
| `event.discarded` | `{seat, tile}` |
| `event.claim_open` | `{tile, from_seat, seats:[...], reason:"discard"\|"rob_kong"}` |
| `event.claimed` | `{seat, from_seat, action:"pong"\|"chow", tile, tiles?}`；吃牌带 `tiles` |
| `event.kongged` | `{seat, kind:"exposed"\|"hidden"\|"added", tile, from_seat?}` |
| `event.kong_score` | `{seat, kind, delta:[4 个整数], enabled}`；`kong_score.enabled=false` 时**不产生该事件** |
| `event.turn_changed` | `{seat, phase, wall_count, after_kong}` |
| `event.claim_timeout` | `{message}`，询问窗口超时按过处理时广播 |
| `event.settled` | `{round_no, dealer_seat, winner_seat, win_type, winning_tile, pattern_id, fan_total, fan_items, score_delta, summary}` |
| `event.game_finished` | `{scores:[...]}`，整场结束（局数打完） |

## 快照 `state.snapshot`

```json
{
  "room": { "code": "DPMPRZ", "name": "周末家庭局 · 10/25", "host_id": 2,
            "rule_name": "家庭标准", "rule_brief": { "...": "见规则文档" } },
  "self_seat": 3,
  "seats": [
    { "seat": 0, "user_id": 2, "display_name": "爸爸", "color": "#C9A063",
      "ready": true, "connected": true, "is_host": true,
      "hand_count": 13, "melds": [ ... ], "round_score": 0, "total_score": 0 }
  ],
  "status": "playing",
  "round_no": 1,
  "dealer_seat": 0,
  "game_total_rounds": 4,
  "hand": [0, 0, 2, 4, 8, 9, 11, 15, 18, 20, 24, 27, 33],
  "drawn": 33,
  "turn": 0,
  "phase": "discard",
  "wall_count": 83,
  "discards": [[], [], [], []],
  "last_discard": { "seat": 2, "tile": 15 },
  "legal": { "actions": [ { "action": "discard" } ] },
  "tenpai": {},
  "deadline": 1792900123.4,
  "claim_deadline": null,
  "result": null
}
```

关键约定：

- **`hand` 只对 `self_seat` 填充**，其他座位只有 `hand_count` 与 `melds`；暗杠对非本人只给 `count=4` 的隐藏副露（`tiles` 为空）
- `drawn`：仅在轮到自己且刚摸牌时非空，用于把新摸的牌单独摆到右侧
- `legal`：`actions` 里是当前允许的动作（`[{action:"discard"}, {action:"hu"}, {action:"kong",kong_kind:"hidden",tiles:[15],label:"暗杠五万"}]`）；claim 阶段额外带 `claim_tile`、`claim_from`、`reason`
- **`deadline` 仅在 `turn_timeout.enabled=true` 且 `phase=discard` 时下发**，关闭后恒为 `null`，前端连倒计时环都不渲染
- **`tenpai` 仅在 `ting_hint.enabled=true` 且轮到自己时下发**，格式 `{"<打出的牌>": [等待的牌...]}`，否则为空对象
- `claim_deadline`：询问窗口截止时间（浮点秒），窗口永远开启，不随出牌超时开关关闭

## 错误码

| code | 中文提示 | 场景 |
| --- | --- | --- |
| `UNAUTHORIZED` | 登录已失效，请重新登录 | token 无效（随后 close 4001） |
| `ROOM_NOT_FOUND` | 房间不存在或已关闭 | 邀请码无效（随后 close 4004） |
| `ROOM_FULL` | 四个座位都坐满了，你先观战吧 | 第 5 人进入 |
| `BAD_MESSAGE` | 消息格式不对 | 信封校验失败 |
| `INTERNAL` | 服务端处理出错，请重试 | 处理单条消息异常，不影响其他人 |
| `NO_SEAT` | 你还在观战，没有座位 | 观战者要点准备/操作 |
| `NOT_HOST` | 只有房主可以开桌 / 只有房主可以开始下一局 | 非房主 |
| `PLAYING` | 牌局正在进行中 | 局中重复开桌 |
| `NOT_ENOUGH` | 还差人，需要 4 位玩家都入座 | 人数不足 |
| `NOT_READY` | 还有玩家没有点准备 | 有人未准备 |
| `NOT_STARTED` | 牌局还没开始 | 未开局就请求下一局 |
| `NOT_SETTLED` | 本局还没结束 | 局中请求下一局 |
| `NOT_PLAYING` | 牌局还没开始或本局已结束 | 不在对局中提交动作 |
| `NOT_YOUR_TURN` | 还没轮到你操作 | 越位操作 |
| `BAD_ACTION` | 现在不能执行「x」/ 缺少动作类型 | 动作与当前阶段不符 |
| `BAD_DISCARD` | 出牌必须且只能选一张 | 出牌张数不对 |
| `NOT_IN_HAND` | 这张牌不在你手里 | 打/杠不在手上的牌 |
| `NO_CLAIM` | 当前没有可响应的牌 | 无询问窗口时响应 |
| `NOT_YOUR_CALL` | 这张牌你没法操作 | 不在候选座位内 |
| `BAD_CHOW` | 吃牌的组合不合法 | 搭子不连续或牌不够 |
| `BAD_KONG` | 暗杠需要手里正好有 4 张相同 / 补杠需要先碰过这张牌 / 杠的类型不合法 | 杠不成立 |
| `NOT_WIN` | 这副牌还没胡 | 强行胡 |
| `ROUND_OVER` | 本局已经结束了 | 结算后再操作 |
| `EMPTY_CHAT` | 消息不能为空 | 空消息 |
| `CHAT_TOO_LONG` | 消息最多 200 个字 | 超长 |
| `CHAT_TOO_FAST` | 说太快啦，歇一下再说 | 5 秒内超过 3 条 |

## 断线与重连

- WS 断开后座位保留 3 分钟（`seat_reserve_seconds`），期间其它座位看到 `connected=false`（红叉图标）
- 前端 `api/ws.ts` 以指数退避重连，重连成功先收 `room.welcome`（含历史聊天），再自动 `state.resync` 拿全量快照，界面完整恢复
- 同一账号可多端在线：服务端按用户维护连接列表，任一连接断开不影响其它连接，也不会误判座位离线
