# 家庭麻将 · 移动侧界面（需求与实现）

> 版本：v1（2026-10-29）
> 范围：手机浏览器版「打牌闭环」，与 PC 版 `/majiangapp/` 并存于 `/mjmobile/`
> 代码位置：`code/frontend`（同一工程第二入口，非独立工程）

---

## 1. 目标与结论

### 1.1 一句话目标

让家人在**手机上**完成「登录 → 进大厅 → 进桌/开桌 → 打牌 → 看战绩」的全流程，牌桌横屏、四方位、单手可玩；PC 版一切照旧。

### 1.2 关键决策（已确认）

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 代码位置 | **不新建 `code/mobile`**，在 `code/frontend` 内做「双入口 + 双构建」 | 逻辑层（api/store/audio/types/utils）只有一份，避免协议改动两端漂移；PC 构建行为保持不变 |
| 第一版范围 | 登录/注册/找回、大厅、牌桌、战绩、家庭（看/切/建） | 打牌闭环优先上线 |
| 不做（指回 PC） | 规则模板编辑、皮肤管理/上传、家庭成员增删改 | 表格、批量上传在小屏上体验极差且易误操作 |
| 牌桌形态 | **横屏**沉浸；竖屏给「请横屏」遮罩 + 一键全屏尝试 | 四家 + 副露 + 14 张手牌 + 动作条在竖屏放不下 |
| 线上入口 | `/majiangapp/`（PC）与 `/mjmobile/`（手机）并存，互不影响 | 同一 nginx、同一 `/majiangapi`、`/majiangws` |
| 登录态 | 同域共享 `localStorage` 的 `mj_token` | PC 登录后手机自动登录，无需重复登录 |

## 2. 页面需求

### 2.1 登录 / 注册 / 找回密码

- 竖屏单列，内容居中，最大宽度 430px；飘浮大牌做背景（12% 透明度，`--mj-tilt` 差异化倾斜）。
- 输入框 ≥48px 高、16px 字号（**iOS 低于 16px 会在聚焦时放大页面**）；主按钮满宽、48px 高、金色实体。
- 错误提示贴在提交按钮上方（红边框条），不使用居中弹窗（小屏上会顶掉键盘焦点）。
- 登录页底部显示服务连通状态（`/api/health`）与版本号；「忘记密码」放在密码标签右侧而非页面底部。
- 注册页：手机号 + 验证码（带 60s 倒计时与「获取验证码」） + 密码/确认 + 昵称 + 同意条款；注册成功回填登录页账号。
- 找回密码：两步式（验证账号 → 设置新密码），第二步顶部显示掩码手机号（`138****0000`）与「重新发送」。
- 注册/找回被服务端关闭时，整页替换为「未开放」说明 + 返回登录，不显示无法提交的表单。

### 2.2 大厅

自上而下：问候与战绩摘要（累计积分/场次/胡牌局数） → 家里进行中的牌桌 → 邀请码入座 → 快捷入口（战绩 / 规则模板[PC] / 我的家庭） → 底部固定「创建牌桌」。

- 顶部栏右侧是**家庭 chip**（首字圆形徽标 + 名称 + 箭头），点击从底部抽屉切换家庭；切家庭后大厅牌桌与战绩整份重拉，不清屏只覆盖。
- 牌桌卡片：桌名 + 邀请码（等宽字体小胶囊）+ 规则族徽标 + 规则名 + 人数/围观数/状态；整卡可点直达牌桌。
- 房主在卡片底部多一行「我是房主，关闭这桌」，二次确认后就地删除卡片（不必先进屋）。
- 邀请码入座：6 格数字框（`inputmode=numeric`、`autocomplete=one-time-code`），支持整串粘贴，输满 6 位自动校验并进桌；座位满但还有围观位时提示改为观战；外家牌桌提示需房主同意。
- 「创建牌桌」拉起底部抽屉：桌名（默认「周末家庭局 · 10/29」）→ 规则族横滑 chips → 模板竖排单选（单选而非两列网格，防止误点）→ 规则摘要 → 「开桌并进入」。
- 规则族未就绪时：模板整列禁用并提示「引擎未就绪」，底部主按钮禁用。

### 2.3 牌桌（横屏，核心）

**纵向三段 + 独立底部操作槽**：

1. **顶栏（≈40px）**：邀请码（点击复制）· 房间名 · 局风/第 N/M 局 · 牌墙剩余 · 连接状态 · 聊天 · 更多
2. **牌桌主体**：`[左家 62px] [对家条 + 中央牌河] [右家 62px]`
   - 对家一条横带：头像（庄家角标）+ 昵称 + 房主/断线/围观图标 + 总分 + 本局分 + 副露（micro 牌）+ 手牌张数
   - 上/下家竖条：头像、昵称、总分、副露竖叠、张数，回合时金色呼吸描边
   - 中央牌河：自己与对家 6 列小牌铺开，上/下家受宽度限制只显示最近 8 张；正中 54px 方块显示牌墙剩余；最后一张打出的牌描金
   - 事件横幅（出牌/碰/杠/胡/超时）从牌河顶部滑入，2.6s 消失
3. **自己区**：头像 + 昵称 + 总分（本局分）+ 倒计时 + 副露（micro，吃牌标注被吃张）→ 手牌整排
4. **底部操作槽（54px）**：动作条 / 出牌确认 / 结算回看 / 提示文案，**永远不覆盖手牌**

**手牌与出牌**：

- 牌宽按容器宽度自适应三档：≥600px → `hand`(38×52)、≥470px → `md`(32×44)、更窄 → `sm`(24×33)，并保留横向滑动兜底。
- 摸到的牌单独放在金线右侧，与整排隔开。
- 听牌张（规则开启听牌提示时）金框高亮，底部状态行显示「N 张可听」。
- **先点选、再确认**：点一张牌只是抬起选中（金边），底部出现「已选 XX / 打出 / 取消」，防误触。

**等人阶段**（未开局）：牌河区域浮出半透明层 —— 已入座人数、准备/取消准备、房主「开始牌局」（全员准备才可点）、房主限时下拉（0 秒=不限时，10–120s）、观战者提示。

**其他浮层**：

- 观战：底部横幅「观战：XXX · 人数/上限 · 切换/取消」；未选对象时弹出选择抽屉（复用 PC `SpectatePanel`）；观战者视角的四方位按其关注对象旋转。
- 聊天：顶栏气泡按钮打开底部抽屉（复用 PC `ChatPanel`），高度 62dvh。
- 更多抽屉：本局规则（底分/番数算法/封顶/吃牌/限时/杠分/听牌提示/牌型）、牌面皮肤（CSS 经典 + 家庭皮肤）、音效（总开关/音量/聊天提示音/试听/解锁状态）、复制邀请码、结束本场牌局、离桌回大厅。
- 结算：复用 PC `ResultModal`（番种、分数构成、赢家手牌）；收起后底部留「第 N 局已结算 · 看结算 · 下一局/查看总账」。
- 全屏浮层集合：等房主确认进桌、被拒/房间已关、房主审批进桌申请、结束牌局二次确认、整场结算、房间已关闭。
- 竖屏闸门：大图标 + 「把手机横过来打牌」 + 「一键进入横屏」（`requestFullscreen` + `screen.orientation.lock('landscape')`，均失败则给 iOS 手动横屏文案）+ 可「先这样看」。

### 2.4 战绩

- 顶部 2×2 统计卡：累计积分、参与场次、最高单场、胡牌局数。
- 积分走势迷你折线（`Sparkline`，按当前筛选区间累积）。
- 筛选胶囊：全部 / 近 30 天 / 近 7 天。
- 场次列表：房名（客队场次带「客队」标签）+ 时间 + 状态 + 四人色点与分数 + 我的得分（正绿负红）。
- 点一场 → 底部抽屉：四人分数卡、本场规则摘要、逐局（番种标签、赢家与胡张、分数变化、终局四家手牌含副露，胡张/点炮张高亮）。

### 2.5 家庭

- 卡片列表：首字圆形徽标 + 名称 + 角色徽章（家长/管理员/成员）+ 编码 + 成员数 + 默认规则族；当前家庭金色描边 + 「当前」角标。
- 操作：切换到当前（已选则禁用并显示「正在使用」）、成员（→ PC 提示）、新建家庭（底部抽屉：名称/编码/默认规则族，创建后直接进大厅）。

## 3. 视觉与交互规范

| 维度 | 规范 |
| --- | --- |
| 材质 | 墨绿绒面背景（径向渐变）+ 半透明面板 + 1px 金线描边；牌面米白、投影短而实 |
| 层次 | 顶栏/底栏压暗（`rgba(7,26,18,.9)`，不用大面积 `backdrop-blur`，中低端安卓会掉帧）；操作区用金色实体按钮做视觉锚点 |
| 触控 | 可点区域 ≥44×44px；用 `:active` 缩放 0.975 代替 hover；`-webkit-tap-highlight-color: transparent`；`touch-action: manipulation` |
| 视口 | `100dvh`（iOS 地址栏收放不跳）；`env(safe-area-inset-*)` 处理刘海与手势条；牌桌 `overscroll-behavior: none` |
| 字号 | 输入框统一 16px 防 iOS 聚焦放大；正文 13px / 说明 11px / 数字用 `font-num`（Noto Serif SC） |
| 动效 | 页面切换 200ms 位移淡入；抽屉 240ms 上滑（`cubic-bezier(.22,.8,.3,1)`）；横幅滑入 200ms；全部尊重 `prefers-reduced-motion` |
| z-index 阶梯 | 顶栏/底栏 40 → 动作条 50 → 抽屉/结算 70 → 全屏浮层 72~75 → 竖屏闸门 90 |
| 安全区 | TabBar、底部操作条、抽屉 footer 都叠加 `env(safe-area-inset-bottom)` |

**Tailwind 踩坑（已修）**：透明度修饰符只认 5 的倍数（`/25`、`/40`、`/95` 有效；`/12`、`/82`、`/96` **不生成任何 CSS**）。移动端代码全部统一为 5 的倍数，或用 `/[0.03]` 形式。

## 4. 技术实现

### 4.1 双入口构建

| 文件 | 改动 |
| --- | --- |
| `code/frontend/vite.config.ts` | `defineConfig(({ command, mode }) => ...)`：`mode === 'mjmobile'` 时 `base='/mjmobile/'`、`outDir='dist-mobile'`、`input='mobile.html'`；否则保持 `base='/majiangapp/'`、`outDir='dist'`、`input='index.html'`。dev 一律 `base='/'`，保留 `/api`、`/ws`、`/majiangapp` 代理 |
| `code/frontend/mobile.html` | 新入口：`viewport-fit=cover` + 禁缩放、`theme-color`、`apple-mobile-web-app-*`、内联 SVG favicon，挂 `/src/mobile/main.ts` |
| `code/frontend/.env.mjmobile` | `VITE_API_BASE=/majiangapi`、`VITE_WS_PATH=/majiangws`（`--mode mjmobile` 不会加载 `.env.production`） |
| `code/frontend/package.json` | 新增 `dev:mobile`（`vite --open /mobile.html`）、`build:mobile`（`vue-tsc --noEmit && vite build --mode mjmobile`） |
| `code/frontend/tailwind.config.js` | `content` 增加 `./mobile.html` |

产物：`dist-mobile/mobile.html`（**不是 index.html**，vite 按源文件名落地）+ `assets/` + `tileart/`(34 张矢量牌面) + `audio/sfx/`(15 个音效)。

**构建目标（重要）**：手机版 `build.target` 显式降到 `['chrome78','safari13','firefox70','edge79']`，PC 版保持 vite 默认。
家里那台华为 Android 12 的预装 Chrome 停在 **78.0.3904.96（2019）**，不认 `?.` 与 `??`；vite 默认按 chrome87 输出会原样保留这两个语法，导致整包 `SyntaxError`、Vue 挂不上，**页面只剩一张 CSS 背景**。降级后产物中 `?.`/`??` 出现次数为 0（构建后可校验）。

配套的 CSS 兜底（写在 `styles/mobile.css`）：`inset` 简写（Chrome 87+）→ `@supports` 展成四边；flex `gap`（Chrome 84+）→ 手牌/副露/按钮组用 margin 兜底；`dvh`（Chrome 108+）→ 统一 `vh` 或 `100vh` 回退；自检层与内联样式同样不用 `inset` 简写。

### 4.2 复用边界

**零改动直接复用**：`api/http.ts`、`api/ws.ts`、`stores/{auth,families,game,skins}`、`composables/useToast`、`audio/*`、`types.ts`、`utils/tile.ts`、`components/ToastHost.vue`、`table/{Tile,ActionBar,ResultModal,SpectatePanel,TurnTimer}.vue`、`ChatPanel.vue`、`Sparkline.vue`。数据流（WS 快照全量替换 + 增量事件播音效）、重连退避、心跳、音效手势解锁全部原样生效。

**向后兼容的 3 处加法式改动**：

1. `components/table/Tile.vue`：`SIZES` 增加 `micro`(20×27) 与 `hand`(38×52) 两档，并扩展 `size` 联合类型 —— PC 不用新档位，渲染不变。
2. `stores/game.ts`：401 兜底的 `window.location.href = '/login'` 改为 `${import.meta.env.BASE_URL}login`（PC 下等价，手机版必需，否则跳到 `/login` 404）。
3. `router/index.ts` → 抽出 `router/guards.ts` 的 `installGuards(router)`，PC 路由与手机路由共用同一套守卫（公开页白名单、`requiresFamily`、`requiresAdmin`、已登录回大厅、`document.title`）。

### 4.4 状态与数据

- 全部走现有 `game` store：`enterRoom(code)` 建立 WS，快照全量替换；`discard / act / pass / toggleReady / startGame / nextRound / endGame / sendChat / followSeat / approveJoin` 与 PC 完全同一套动作。
- 相对方位推导：`self = selfSeat ?? spectateSeat ?? 0`，`right/left/across = (self±1/2/3) % 4`；观战时按「被关注的人」旋转，保证手牌区永远在底部。
- 出牌确认：本地 `selected`，`canDiscard = isMyTurn && hasAction('discard')`；动作条只在存在非 `discard` 动作（吃/碰/杠/胡/过）时出现。
- 结算收起：`dismissedRound` 记住已收起的局号，`settled` 阶段才允许收起，底部常驻「看结算 / 下一局」。

| 登录 | 卡片居中、按钮满宽、服务状态与版本号可见；飘浮牌不遮挡输入区 |
| 大厅 | 统计 3 宫格、牌桌卡片、邀请码 6 格、固定 CTA 与 TabBar 均正确让位 |
| 开桌抽屉 | 桌名预填、规则族 chip、模板单选、规则摘要、底部主按钮完整可见 |
| 战绩 | 2×2 统计卡、走势、筛选胶囊、场次列表（含「客队」标记）均正常 |
| 战绩详情 | 四人分数、规则摘要、番种标签、终局四家手牌（micro 牌 + 副露 + 胡张高亮）正常 |
| 家庭 | 卡片、角色徽章、当前高亮、成员入口、新建家庭抽屉正常 |
| 牌桌（竖屏） | 闸门遮罩生效：深色铺底 + 一键横屏 + 文案 |

修复过程中发现并已解决：非 5 倍数透明度类不生成（闸门/浮层背景透明）、聊天悬浮球遮挡手牌（移入顶栏）、「可听张数」胶囊挤压手牌（移到状态行）、`剩余` 误写成繁体、`dist-mobile` 清理需要先手动删目录（`vite` 的 `emptyOutDir` 在受控环境会被拦截）。

已知限制：

- 上家/下家牌河只显示最近 8 张（横屏中央高度有限），自己与对家牌河完整。
- iOS Safari 不支持 `screen.orientation.lock`，只能引导手动横屏；`requestFullscreen` 在 iPhone Safari 上同样不可用。
- 手机版不含规则模板编辑、皮肤上传、成员管理；入口处统一提示并给出 PC 地址。
- **老内核**：Chrome 78（华为 Android 12 预装）已按上面的 target 与 CSS 兜底跑通，但 `:where()`、`aspect-ratio`、flex `gap` 等仍是「不可用/需兜底」状态；该版本浏览器也无法享受 `dvh` 的自适应高度。建议家人改用 Edge / Firefox / Via 等较新内核浏览器。
- 发布侧策略：`assets/` 只增不删（保留 14 天），避免浏览器缓存了旧 `mobile.html` 时引用的旧哈希 JS 已被删除而 404 白屏；`mobile.html` 另设 `no-cache`。
