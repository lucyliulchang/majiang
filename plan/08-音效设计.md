> 上游：[家庭麻将总体规划文档.md](家庭麻将总体规划文档.md)、[04-协议设计.md](04-协议设计.md)、[05-UI设计.md](05-UI设计.md)
> 本文是**音效触发规则、优先级、资源规格与降级策略的唯一权威**。

## 1. 范围与原则

### 1.1 范围内

- 牌桌操作音效：发牌、掷骰、摸牌、出牌、吃、碰、明杠/暗杠/补杠、胡牌、荒庄、可操作询问、轮到自己、超时、聊天提示。
- 用户级音效开关、音量与聊天提示子开关（随 `mj_user_pref` 持久化）。
- 资源缺失、浏览器限制、后台标签页的静音降级。

### 1.2 范围外（明确不做）

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 背景音乐（BGM） | **不做** | 家庭场景长时间开局，BGM 干扰交谈；也避免版权与流量 |
| 语音播报 / TTS / 服务端合成 | **不做** | 需服务端合成与多语言，收益低 |
| **客户端预置牌面报牌（真人语音）** | **做**（v1.1 追加） | 出牌后播报该张牌的女声报牌；**纯前端资源**、只消费既有 `event.discarded.tile`、协议零改动；见 §2.1 与 §4.5 |
| 服务端混音 / 房间同步播放 / 音效落库 | 不做 | 音效是纯客户端表现，服务端无需感知 |
| 家庭自定义音效包上传 | 不做（首期） | 与皮肤不同，音效个性化需求弱，先固定一套 |
| 第三方版权音源 | **有限放开**（v1.1 追加） | 牌面报牌允许使用 `plan/majiang_sound/women_mp3` 的第三方女声素材（源仓库无 LICENSE、权利归属不明，**风险已登记**，见 §6.3）；**v1.2 起 6 个叫牌音同样取用该素材**（走 `voice/` 目录的枚举键通道），其余 9 个音效仍只用自制录音或 CC0 |

原则：

1. 音效是**补充反馈**，不能成为唯一信息通道（关键状态仍需文字/颜色表达）。
2. 全站**只有 SFX，没有 BGM**；除预加载外无持续音频开销。
3. 音效不新增协议字段：只消费既有 WS 事件（04 §9.4），不监听 `spectate.*`。
4. 任何异常（缺文件、解码失败、自动播放被拦）一律**静音降级**，不得影响对局。

> **枚举共 15 个键**（v1.2）：其中 **6 个叫牌键**（`hu_voice`/`pong_voice`/`chow_voice`/`kong_exposed_voice`/`kong_hidden_voice`/`kong_added_voice`）指向 `voice/` 目录的女声素材，其余 9 个指向 `sfx/` 目录的合成音。
> 旧的 6 个合成键 `hu`/`pong`/`chow`/`kong_exposed`/`kong_hidden`/`kong_added` 已**从枚举中移除**（v1.2）：**文件仍保留**在 `public/audio/sfx/`（不再被引用、不再触发），便于回滚与对照。
> 34 个牌面人声**不在本表** —— 它们是动态键，走 §4.5 的 `playVoice()` 通道，不进 `SOUND_KEYS` 预加载清单。

补充规则：

- `state.snapshot`、`room.welcome`、WS 心跳 `pong`（无 `data` 的消息类型，与碰牌音效键 `pong_voice` 不同域）、`error`、`event.ready_changed`、`event.paused`、`event.game_finished` **不播音效**（避免重连补播与噪声）。
- 抢杠胡不单独做音效：窗口开启由 `claim` 提示，成交由 `event.settled` 播 `hu_voice`。
- 同一局内 `event.settled` 若含多个赢家（四川多赢家），只播一次 `hu_voice`。
- 自己的操作**不做本地预播放**，统一等服务器事件，天然避免重复与前后端时序差异。
- 观战者 `self_seat=null`：`claim`/`turn` 因条件含自身座位而永不触发，`draw` 按「他人 40%」处理，其余事件照常；切换观战目标不补播历史音效。

### 2.1 牌面报牌（人声，v1.1 追加）

出牌后除原有落牌底噪（`discard`）外，**叠加**播放该张牌的**女声报牌音**：一万～九万、一筒～九筒、一条～九条、东南西北中发白，共 **34 个**，逐张区分。

| 项 | 口径 |
| --- | --- |
| 触发事件 | `event.discarded`（04 §9.4），**不新增任何 WS 事件或字段**；payload 已含 `tile`（0–33） |
| 与底噪关系 | `discard` 底噪**保留**，人声**叠加**在其上（两者同时播放，不是替换） |
| 默认音量 | 与 `discard` 同档（55）；不随座位衰减——牌面是**公共信息**，衰减会导致"听不清是谁打的" |
| 优先级 | **P3**（与 `discard` 同级） |
| 键粒度 | 34 个资源对应 34 张牌，**按牌面各算一个键**；同一张牌 150 ms 内重复出牌按既有同键去重丢弃 |
| 不替换的键 | `exhausted`/`claim`/`turn`/`draw`/`timeout`/`dice`/`deal`/`chat` 无人声素材，保持原样；**叫牌音（吃/碰/胡/杠）自 v1.2 起改用人声，见 §2.2** |
| 关闭方式 | 随**总开关 + 音量**生效；本轮**不新增**独立子开关（避免 `mj_user_pref` 加列与协议扩展） |

### 2.2 叫牌人声（v1.2 追加）

吃 / 碰 / 胡 / 明杠 / 暗杠 / 补杠 六种叫牌改用**女声素材**，与牌面报牌同一套 `voice/` 目录资源。

| 项 | 口径 |
| --- | --- |
| 触发事件 | `event.claimed`（`action=pong` / `action=chow`）、`event.kongged`（`kind=exposed`/`hidden`/`added`）、`event.settled`（有赢家）—— **不新增任何 WS 事件或字段** |
| 音效键 | `chow_voice` / `pong_voice` / `hu_voice` / `kong_exposed_voice` / `kong_hidden_voice` / `kong_added_voice`，共 **6 个**，与旧合成键**一一对应** |
| 与旧合成音的关系 | **互斥、不叠加**：同一事件只播人声；旧合成键已从 `SOUND_SPECS` 移除（**文件保留**在 `public/audio/sfx/`，不再被引用、不再触发） |
| 音量 / 优先级 | **沿用旧值**：`hu_voice` 90 / P0；`pong_voice` 70 / P2；`chow_voice` 65 / P2；`kong_*_voice` 75 / P1 |
| 与牌面报牌的关系 | 两套人声**互不干扰**：叫牌人声走**枚举键通道**（`playSound`），牌面报牌走**动态键通道**（`playVoice`，§4.5），各自独立去重与降级 |
| 播放条件 | 与旧合成音完全一致（任意座位都播；`hu_voice` 一局只播一次，多赢家不叠加；荒庄只播 `exhausted` 不播 `hu_voice`） |
| 关闭方式 | 随**总开关 + 音量**生效；不新增独立子开关 |

## 3. 优先级、并发与限流

| 级别 | 键 | 说明 |
| --- | --- | --- |
| P0 | `hu_voice` | 结算主角音，可抑制其他音效 |
| P1 | `exhausted`、`kong_*_voice`、`claim` | 大动作与可操作提示 |
| P2 | `pong_voice`、`chow_voice`、`turn` | 中等反馈 |
| P3 | `discard`、`draw`、`timeout`、**牌面报牌** | 高频轻音 |
| P4 | `dice`、`deal`、`chat` | 氛围音，最易被丢弃 |

规则：

1. 同一时刻最多 **4 个并发音**；超出时丢弃正在播放的最低优先级（同级别丢更早的），丢弃用 30ms 线性淡出，避免硬切爆音。
2. 同键 **150ms** 内去重（连续快速出牌/摸牌不叠成噪音）。
3. P0 播放后 **200ms** 内到达的 P3/P4 直接丢弃，不排队；任何音效排队超过 300ms 即丢弃（宁可无声，不可延迟）。
4. 重连/恢复可见后 **800ms 静音期**，用于吞掉快照恢复与突兀事件。
5. `visibilitychange` 为隐藏时 `AudioContext.suspend()`，恢复可见时 `resume()`；不补播。
6. **牌面报牌**（§2.1）额外受一条**全局最短间隔 250ms** 约束：任意两张牌的报牌声之间至少间隔 250ms，间隔不足者直接丢弃（不排队）。原因：牌面键随牌面变化，既有「同键 150ms 去重」挡不住"连续打不同牌"造成的密集人声。

## 4. 客户端实现

### 4.1 目录

```text
code/frontend/
├── public/audio/sfx/            # 15 个 mp3 + LICENSE.md（合成音；其中 6 个叫牌合成音自 v1.2 起保留文件但不再触发）
├── public/audio/voice/          # 40 个 mp3 + LICENSE.md（人声：34 牌面报牌 + 6 叫牌）
└── src/audio/
    ├── soundKeys.ts             # 键 → 文件、目录(dir)、基础音量、优先级
    ├── voiceMap.ts              # tile(0–33) → 报牌素材基名 + URL（牌面报牌专用动态通道）
    ├── audioManager.ts          # 单例：预加载/解锁/播放/限流/降级
    └── useGameSounds.ts         # game store 事件 → play(key) / playVoice(base)
```

### 4.2 选型

| 项 | 方案 | 理由 |
| --- | --- | --- |
| 引擎 | Web Audio API（`AudioContext` + `decodeAudioData` + `GainNode`） | 首次解码后延迟 <50ms，可并发混音、按键调增益 |
| 回退 | `HTMLAudioElement` 池（4 个） | `AudioContext` 不可用（极老 WebView）时仍能出声 |
| 触发点 | `useGameSounds` 挂在 `stores/game.ts` 的 `handleEvent` / `handleMessage`，组件不直接调用 | 避免音效散落在组件，事件源唯一 |
| 预加载 | `room.welcome` 后并发加载全部音效 | 进桌即就绪；`Promise.allSettled`，单个失败不影响其他 |
| 主增益 | 用户音量 / 100，上限 1.0 | 统一控制；不做动态压缩 |
| 牌面人声 | 独立 `public/audio/voice/` 目录 + 运行时拼 URL，**不扩 `SoundKey` 联合类型** | `SoundKey` 是字面量联合类型，扩到 49 项会让预加载一次拉 49 个文件、首屏流量与 `audioState.total` 全部失控；动态键只需一张 34 项映射表 |
| 叫牌人声 | **枚举键 + `SoundSpec.dir` 字段**（v1.2）：6 个叫牌键用 `dir:'voice'` 指向 `voice/`，其余键 `dir` 缺省即 `sfx/` | 叫牌音是**静态枚举**（只有 6 个），不需要动态键；`sfxUrl()` 按 `dir` 拼目录即可，`audioManager` 的缓冲/加载/降级/去重全部以 `SoundKey` 为键，**零改动**；`SOUND_KEYS` 仍 15 项 → **预加载文件数不变**，只是 6 个来源换成 `voice/` |

### 4.3 自动播放与解锁

- `AudioContext` 单例在**首次用户手势**（登录点击、进入牌桌点击）中创建并 `resume()`；失败则挂起，等下一次手势重试。
- 未解锁前不播放，也不弹窗打断；`ScoreBoard` 音效按钮上用角标「♪」提示可开启。
- iOS Safari 受硬件静音键影响可能无声，属浏览器行为，文档说明，不当作缺陷。

### 4.4 降级矩阵

| 场景 | 表现 |
| --- | --- |
| 单个 mp3 404 / 解码失败 | 该键标记 `unavailable`，后续跳过，`console.debug` 一次；其余音效正常 |
| 整个目录缺失 | 全静音，对局与 UI 无异常，控制台无 `error` |
| `AudioContext` 构造失败 | 切 HTMLAudio 池；仍失败则全静音 |
| `sound_enabled=false` | 不创建音源；不再发起音频请求 |
| `navigator.connection.saveData` | 不预加载，按需拉取；失败静音 |
| 后台标签页 | 暂停播放，不累积队列 |

### 4.5 牌面人声报牌实现（v1.1 追加）

**映射表（tile 0–33 → 素材基名）**

| tile 区间 | 花色/字牌 | 素材基名 | 前端 `tileKey()` |
| --- | --- | --- | --- |
| 0–8 | 万 | `1wan` … `9wan` | `1m` … `9m` |
| 9–17 | 筒（饼） | `1tong` … `9tong` | `1p` … `9p` |
| 18–26 | 条 | `1tiao` … `9tiao` | `1s` … `9s` |
| 27 | 东 | `dongfeng` | `east` |
| 28 | 南 | `nanfeng` | `south` |
| 29 | 西 | `xifeng` | `west` |
| 30 | 北 | `beifeng` | `north` |
| 31 | 中 | `zhong` | `red` |
| 32 | 发 | `fa` | `green` |
| 33 | 白 | `bai` | `white` |

- 素材基名**不是** `tileKey()`（`utils/tile.ts` 的 `1m/1p/1s/east…white`），两者必须经 `voiceMap.ts` 显式映射，不得互相替代。
- 素材目录里的 6 个叫牌音（`hu`/`pong`/`chow`/`kong_exposed`/`kong_hidden`/`kong_added`）**自 v1.2 起也复制进 `voice/`**，但**不走本节的动态通道** —— 它们是静态枚举键，见 §2.2 与 §4.2 的 `dir` 字段。

**加载策略（不进 `SOUND_KEYS` 预加载清单）**

1. 34 个 mp3 合计约 300 KB，若随进桌一次性预加载会把首屏流量抬高约 3 倍 → **不加入 `SOUND_KEYS`**，`preloadSounds()` 仍只拉 15 个 SFX；
2. 报牌首次播放时按需加载（沿用既有降级语义：**本次静音**，`console.debug` 一次），第二次起正常出声；
3. 进桌后用空闲时段（`requestIdleCallback`，无则 `setTimeout`）**分批预热**（每批 4 个，共 9 批），把"首次静音"收敛到开局头几手；
4. `navigator.connection.saveData` 为真时**不预热**，全部按需加载（省流量模式接受首次静音）。

**限流**

- 人声走 `audioManager` 的**同一套**并发/优先级/淡出内核：优先级 P3，受 `MAX_CONCURRENT = 4` 约束；
- 额外受 §3 规则 6 的**全局 250ms 最短间隔**约束（牌面键互不相同，同键 150ms 去重对"连续打不同牌"不生效）；
- 与 `discard` 底噪**同时**播放：两者同为 P3，在并发上限内可共存；
- `hu`（P0）后 200ms 内到达的报牌声按 §3 规则 3 丢弃 —— 结算瞬间最后一张牌的报牌可能不响，**属预期**。

**降级**

| 场景 | 表现 |
| --- | --- |
| 单个人声 mp3 404 / 解码失败 | 该牌面标记 `unavailable`，后续播该牌静音，其余 33 个正常，控制台 `console.debug` 一次 |
| `voice/` 目录整体缺失 | 牌面报牌整体静音，15 个 SFX 与对局完全不受影响 |
| 自动播放被拦 | 与既有 SFX 同一路径：解锁前不播，不报错 |

| `code/deploy/nginx-majiang.conf` | 修改 | 新增 `/majiangapp/audio/voice/` 与 `/mjmobile/audio/voice/` 两条 30 天缓存规则 |

实现要点：

1. **`playVoice()` 接受基名或完整 URL**：`voiceUrlOf(tile)` 的返回值与基名（`1wan`）都能传入，内部经 `voiceBaseFromTarget()` 归一化，且**只认表内 34 个基名** —— 防止任意 URL 被当成音频资源拉取。
2. **映射顺序即 tile 0–33**：万 0–8 → 筒 9–17 → 条 18–26 → 东南西北中发白 27–33；与 `tileKey()` 的逐项对照见上表，**不得混用**。
3. **限流三条并列生效**：同基名 150ms 去重、全局 250ms 最短间隔、P0（`hu`）后 200ms 抑制（§3 规则 3）。
4. **额外保护（实现补充）**：`hu`（P0）**正在播放期间**（不止 200ms）到达的报牌一律丢弃 —— 落实「人声音量不得盖过 `hu`（P0）」的硬约束。
5. **未加载时**：按需 `fetch` + `decodeAudioData`，**本次静音**并 `console.debug` 一次（每基名只提示一次）；加载失败则该基名标记 `unavailable`（该牌面永久静音，其余 33 个照常）。
6. **`preloadVoices()`**：进桌后 `requestIdleCallback`（无则 `setTimeout`）分批预热，每批 4 个、共 9 批；`navigator.connection.saveData` 为真时**不预热**；解锁前调用则挂起、解锁后补跑。`preloadSounds()` **仍然只拉 15 个 SFX**，`audioState.loaded/total` 仍只统计 SFX（人声单独记账）。
7. **产物路径**：`vite` `base` 为 `/majiangapp/`（PC）与 `/mjmobile/`（手机版），`public/audio/voice/` 原样落地为 `dist/audio/voice/`、`dist-mobile/audio/voice/`；运行时 URL 为 `/majiangapp/audio/voice/1wan.mp3` 与 `/mjmobile/audio/voice/1wan.mp3`，与 nginx 两条 `location` 前缀一一对应。

1. **枚举键 + `dir` 字段**：`SoundSpec.dir` 缺省即 `'sfx'`；同名文件在 `sfx/` 与 `voice/` 各有一份，靠 `dir` 区分 —— `sfxUrl()` 返回 `${BASE_URL}audio/${dir ?? 'sfx'}/${file}`。
2. **`SOUND_KEYS` 仍 15 项**：9 个指向 `sfx/`、6 个指向 `voice/`；`SOUND_KEYS` / `SOUND_URLS` / `priorityOf()` 均由 `SOUND_SPECS` 派生，**预加载请求数不变**（仍 15 个，其中 6 个来自 `voice/`）。

6. **不新增 `playVoice()` 分支**：叫牌音不进入 `voiceMap.ts` 的 34 项白名单，`preloadVoices()` 仍只预热 34 个牌面音；6 个叫牌音随 `preloadSounds()` 的 15 个请求一起加载。

## 7. 与状态同步的边界

1. 音效**只由增量事件**驱动；快照（`state.snapshot`）与欢迎包（`room.welcome`）永不触发声音。
2. 断线重连：先 `room.welcome` 再 `state.snapshot`，全程静音；恢复 800ms 后才允许播放。
3. `event.round_restarted`（无杠重发）播 `deal`，不播 `hu_voice`/`exhausted`。
4. 有杠荒庄播 `exhausted`，同时弹结算；无杠重发只有 toast，不弹结算（与 05 §4.5 一致）。
5. 暂停/恢复（`event.paused`）无声，避免把暂停误解为牌局事件。
