# 08 · 音效设计

> 状态：已评审（2026-10-27）
> 上游：[家庭麻将总体规划文档.md](家庭麻将总体规划文档.md)、[04-协议设计.md](04-协议设计.md)、[05-UI设计.md](05-UI设计.md)
> 本文是**音效触发规则、优先级、资源规格与降级策略的唯一权威**。

## 1. 范围与原则

### 1.1 范围内

- 牌桌操作音效：发牌、掷骰、摸牌、出牌、吃、碰、明杠/暗杠/补杠、胡牌、荒庄、可操作询问、轮到自己、超时、聊天提示。
- 用户级音效开关、音量与聊天提示子开关（随 `mj_user_pref` 持久化）。
- 资源缺失、浏览器限制、后台标签页的静音降级。

### 1.2 范围外（明确不做）

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 背景音乐（BGM） | **不做** | 家庭场景长时间开局，BGM 干扰交谈；也避免版权与流量 |
| 语音播报 / TTS / 真人报牌 | 不做 | 需服务端合成与多语言，收益低 |
| 服务端混音 / 房间同步播放 / 音效落库 | 不做 | 音效是纯客户端表现，服务端无需感知 |
| 家庭自定义音效包上传 | 不做（首期） | 与皮肤不同，音效个性化需求弱，先固定一套 |
| 第三方版权音源 | 不使用 | 只用自制录音或 CC0 资源 |

原则：

1. 音效是**补充反馈**，不能成为唯一信息通道（关键状态仍需文字/颜色表达）。
2. 全站**只有 SFX，没有 BGM**；除预加载外无持续音频开销。
3. 协议零改动：全部由既有 WS 事件（04 §9.4）驱动，不新增字段。
4. 任何异常（缺文件、解码失败、自动播放被拦）一律**静音降级**，不得影响对局。

## 2. 音效清单与触发映射

| 音效键 | 文件 | 触发事件（04 §9.4） | 播放条件 | 默认音量 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| `hu` | `hu.mp3` | `event.settled` | `winners` 非空；一局只播一次（多赢家不叠加） | 90 | P0 |
| `exhausted` | `exhausted.mp3` | `event.settled` | `is_draw=true`（有杠荒庄），不播 `hu` | 55 | P1 |
| `kong_exposed` | `kong_exposed.mp3` | `event.kongged` | `kind=exposed` | 75 | P1 |
| `kong_hidden` | `kong_hidden.mp3` | `event.kongged` | `kind=hidden` | 75 | P1 |
| `kong_added` | `kong_added.mp3` | `event.kongged` | `kind=added` | 75 | P1 |
| `claim` | `claim.mp3` | `event.claim_open` | 仅 `seats` 含 `self_seat`（含抢杠窗口） | 50 | P1 |
| `pong` | `pong.mp3` | `event.claimed` | `action=pong`，任意座位 | 70 | P2 |
| `chow` | `chow.mp3` | `event.claimed` | `action=chow`，任意座位 | 65 | P2 |
| `turn` | `turn.mp3` | `event.turn_changed` | `seat==self_seat` 且 `phase=discard` | 45 | P2 |
| `discard` | `discard.mp3` | `event.discarded` | 任意座位（含自己） | 55 | P3 |
| `draw` | `draw.mp3` | `event.drawn` | 任意座位；自己 100% 增益，他人 40% | 35 | P3 |
| `timeout` | `timeout.mp3` | `event.auto_discard` / `event.claim_timeout` | 任意 | 50 | P3 |
| `dice` | `dice.mp3` | `event.seats_drawn` | 每圈抽座时一次 | 60 | P4 |
| `deal` | `deal.mp3` | `event.round_started` / `event.round_restarted` | 开局与无杠重发 | 50 | P4 |
| `chat` | `chat.mp3` | `chat.message` | 聊天面板未聚焦、`login_id` 非空（系统播报不响）、且 `chatSoundFlag=1` | 40 | P4 |

补充规则：

- `state.snapshot`、`room.welcome`、WS 心跳 `pong`（无 `data` 的消息类型，与碰牌音效键 `pong` 不同域）、`error`、`event.ready_changed`、`event.paused`、`event.game_finished` **不播音效**（避免重连补播与噪声）。
- 抢杠胡不单独做音效：窗口开启由 `claim` 提示，成交由 `event.settled` 播 `hu`。
- 同一局内 `event.settled` 若含多个赢家（四川多赢家），只播一次 `hu`。
- 自己的操作**不做本地预播放**，统一等服务器事件，天然避免重复与前后端时序差异。

## 3. 优先级、并发与限流

| 级别 | 键 | 说明 |
| --- | --- | --- |
| P0 | `hu` | 结算主角音，可抑制其他音效 |
| P1 | `exhausted`、`kong_*`、`claim` | 大动作与可操作提示 |
| P2 | `pong`、`chow`、`turn` | 中等反馈 |
| P3 | `discard`、`draw`、`timeout` | 高频轻音 |
| P4 | `dice`、`deal`、`chat` | 氛围音，最易被丢弃 |

规则：

1. 同一时刻最多 **4 个并发音**；超出时丢弃正在播放的最低优先级（同级别丢更早的），丢弃用 30ms 线性淡出，避免硬切爆音。
2. 同键 **150ms** 内去重（连续快速出牌/摸牌不叠成噪音）。
3. P0 播放后 **200ms** 内到达的 P3/P4 直接丢弃，不排队；任何音效排队超过 300ms 即丢弃（宁可无声，不可延迟）。
4. 重连/恢复可见后 **800ms 静音期**，用于吞掉快照恢复与突兀事件。
5. `visibilitychange` 为隐藏时 `AudioContext.suspend()`，恢复可见时 `resume()`；不补播。

## 4. 客户端实现

### 4.1 目录

```text
code/frontend/
├── public/audio/sfx/            # 15 个 mp3 + LICENSE.md
└── src/audio/
    ├── soundKeys.ts             # 键 → 文件、基础音量、优先级、时长
    ├── audioManager.ts          # 单例：预加载/解锁/播放/限流/降级
    └── useGameSounds.ts         # game store 事件 → play(key)
```

### 4.2 选型

| 项 | 方案 | 理由 |
| --- | --- | --- |
| 引擎 | Web Audio API（`AudioContext` + `decodeAudioData` + `GainNode`） | 首次解码后延迟 <50ms，可并发混音、按键调增益 |
| 回退 | `HTMLAudioElement` 池（4 个） | `AudioContext` 不可用（极老 WebView）时仍能出声 |
| 触发点 | `useGameSounds` 挂在 `stores/game.ts` 的 `handleEvent` / `handleMessage`，组件不直接调用 | 避免音效散落在组件，事件源唯一 |
| 预加载 | `room.welcome` 后并发加载全部音效 | 进桌即就绪；`Promise.allSettled`，单个失败不影响其他 |
| 主增益 | 用户音量 / 100，上限 1.0 | 统一控制；不做动态压缩 |

### 4.3 自动播放与解锁

- `AudioContext` 单例在**首次用户手势**（登录点击、进入牌桌点击）中创建并 `resume()`；失败则挂起，等下一次手势重试。
- 未解锁前不播放，也不弹窗打断；`ScoreBoard` 音效按钮上用角标「♪」提示可开启。
- iOS Safari 受硬件静音键影响可能无声，属浏览器行为，文档说明，不当作缺陷。

### 4.4 降级矩阵

| 场景 | 表现 |
| --- | --- |
| 单个 mp3 404 / 解码失败 | 该键标记 `unavailable`，后续跳过，`console.debug` 一次；其余音效正常 |
| 整个目录缺失 | 全静音，对局与 UI 无异常，控制台无 `error` |
| `AudioContext` 构造失败 | 切 HTMLAudio 池；仍失败则全静音 |
| `sound_enabled=false` | 不创建音源；不再发起音频请求 |
| `navigator.connection.saveData` | 不预加载，按需拉取；失败静音 |
| 后台标签页 | 暂停播放，不累积队列 |

## 5. 设置与持久化

牌桌 `ScoreBoard` 增加「音效」按钮（与「皮肤」并列），点击弹 popover：

| 控件 | 说明 |
| --- | --- |
| 总开关 | 开/关全部 SFX |
| 音量滑块 | 0–100，步进 5，拖动即时生效（本地增益，不发请求） |
| 试听 | 播放 `discard.mp3`，用于调音量 |
| 聊天提示 | 独立开关，对应既有 `chatSoundFlag` |

存储：

- 持久化字段见 [02 §3.4](02-数据库设计.md)：`mj_user_pref.soundEnabledFlag`（默认 `'1'`）、`soundVolume`（默认 `70`）、`chatSoundFlag`（已有）。
- 接口见 [04 §4](04-协议设计.md)：`GET/PUT /api/user/pref` 增加 `sound_enabled`、`sound_volume`。
- 前端 `localStorage`（`mj.sound.enabled` / `mj.sound.volume`）做首屏即时生效；服务端返回后覆盖；写请求 500ms 防抖，失败回滚 UI 并 toast。
- 默认：开启、音量 70、聊天提示开启。**没有 BGM 开关**，因为不存在 BGM。

## 6. 资源规格

| 项 | 规格 |
| --- | --- |
| 格式 | MP3（MPEG-1 Layer III），单声道，44.1 kHz，96–128 kbps |
| 时长 | 0.08–1.2s；`hu` ≤1.5s；`deal` ≤1.5s |
| 体积 | 单文件 ≤40 KB，合计 ≤400 KB |
| 电平 | 峰值 ≤ −1 dBFS，无直流偏移；响度统一，避免忽大忽小 |
| 命名 | 与 `soundKeys.ts` 一致的 `snake_case`，禁止中文与空格 |
| 授权 | 自制录音或 CC0；`public/audio/sfx/LICENSE.md` 记录来源与许可 |
| 缓存 | `Cache-Control: public, max-age=2592000`（30 天）；替换资源须改文件名或加 `?v=`，不依赖强制刷新 |

录制建议：

- `discard` / `pong` / `kong_*`：真实牌落毡面，近距单 mic，避免桌面共振。
- `draw` / `deal`：牌墙摩擦 + 轻碰，`deal` 可叠加 3–4 张连发。
- `dice`：两颗骰子在毡面滚动后落定。
- `hu`：短促上行提示音或真人一声「胡」，≤1.5s，不用旋律。
- 首期允许先用合成音占位，但必须满足上述电平与时长，后续替换不改代码。

## 7. 与状态同步的边界

1. 音效**只由增量事件**驱动；快照（`state.snapshot`）与欢迎包（`room.welcome`）永不触发声音。
2. 断线重连：先 `room.welcome` 再 `state.snapshot`，全程静音；恢复 800ms 后才允许播放。
3. `event.round_restarted`（无杠重发）播 `deal`，不播 `hu`/`exhausted`。
4. 有杠荒庄播 `exhausted`，同时弹结算；无杠重发只有 toast，不弹结算（与 05 §4.5 一致）。
5. 暂停/恢复（`event.paused`）无声，避免把暂停误解为牌局事件。

## 8. 验收清单

1. 四人同房：A 出牌，四人都听到且只响一次；关掉 A 的音效不影响他人。
2. 自己摸牌为正常音量，他人摸牌明显更轻（约 40%）。
3. 吃、碰、明杠、暗杠、补杠、胡各自命中对应音效，无错配。
4. 胡牌后 200ms 内的出牌/摸牌/聊天音被抑制，不出现叠响。
5. 荒庄只播 `exhausted`，不播 `hu`；无杠重发播 `deal`，局号与局风不变。
6. 音效关闭后全场静音；刷新、重登、换浏览器后仍为关闭（pref 生效）。
7. 音量 0/50/100 三档主观可辨，拖完立即生效并持久化。
8. 删除任意一个 mp3：该音效静音，其余正常，控制台无 `error`，对局可打完。
9. 首次进入未交互前不自动出声；交互后正常；被拦截时无报错。
10. 断线重连不补播历史事件，无连续爆音；切后台再回来不重叠。
11. Network 面板全程无 BGM/音频流请求，仅进桌时 15 个 SFX（可缓存命中）。
12. 375px 下可打开音效 popover 并完成开关与调音量，不遮挡操作栏。
