# 05 · UI 设计

> 状态：v1.1.0（2026-10-30；新增吃牌选牌态、胡优先文案、结算庄标、提示语字号档位）；**2026-10-31 追加：结算页「胡张标记」规格（金色「胡」角标 + 双层描金）**
> 上游：[家庭麻将总体规划文档.md](家庭麻将总体规划文档.md)、[04-协议设计.md](04-协议设计.md)
> 本文是**视觉规范与牌面资源规格的唯一权威**。

## 1. 设计目标

1. **一桌一世界**：牌桌是主角，界面退到背景；深绿毡面 + 米色牌面 + 金色描边是识别度最高的组合。
2. **家人可用**：字号偏大、按钮偏大、确认动作明确；不用悬停才能发现的功能。
3. **状态一眼可辨**：轮到谁、是否断线、是否准备、是否听牌、是否封顶，靠颜色 + 文案双通道表达。
4. **可换肤但不破版**：牌面图片是"贴图"，尺寸与布局由 CSS 决定；缺图自动回退，不出现空洞。
5. **移动端能打完一局**：手牌可横向滚动、操作栏固定可达、聊天用抽屉。

### 2.2 字体与排版

- `font-sans`：`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
- `font-num`：`"Noto Serif SC", Georgia, serif`；牌面汉字、番数、分数使用。
- 字号阶梯：`xs 12 / sm 14 / base 16 / lg 18 / xl 20 / 2xl 24 / 3xl 30 / 5xl 48`；牌桌比分用 `5xl`。
- 小标签 `tracking-[0.28em]`，全大写英文或短中文；正文不使用字距。
- **牌桌提示语字号档位（v1.1.0，吃碰提示整体 +2 号）**：

  | 位置 | 桌面 | 手机横屏 | Tailwind（桌面/手机） |
  | --- | --- | --- | --- |
  | 牌桌横幅（吃/碰/抢杠/轮到） | 14px | 13px | `text-sm` / `text-[13px]` |
  | 动作条标签（来牌/抢杠） | 13px | 13px | `text-[13px]` |
  | 动作条按钮（胡/碰/杠/吃/过） | 16px | 16px | `text-base` |

  横幅同时把内边距提到 `px-4 py-2`（手机 `px-3.5 py-1.5`），并保持 `pointer-events-none` 与 `truncate`，不得遮挡牌河。

| `/` | `LobbyView` | 当前家庭大厅：统计、牌桌、邀请码 | 登录 |

| `/room/:code` | `RoomView` | 牌桌 | 家庭成员 |
| `/history` | `HistoryView` | 战绩与明细 | 登录 |
| `/admin/skins` | `SkinsView` | 皮肤管理（列表/上传/发布） | 家庭管理员/系统管理员 |
| `/admin/skins/:skinCode` | `SkinEditView` | 单皮肤资源管理 | 同上 |
| `/404` | `NotFoundView` | 兜底 | 公开 |

全局：

- `AppHeader`：品牌 → 家庭切换器（徽标 + 名称）→ 大厅/规则/战绩 → 皮肤入口（管理员）→ 用户胶囊（昵称、成员弹窗、退出）。
- 移动端：`<768px` 折叠为「品牌 + 家庭 + 汉堡菜单」，菜单含导航与用户操作。
- 路由守卫：token 判定 + `meta.requiresFamily`（无家庭时跳 `/families`）+ `meta.requiresAdmin`（家庭管理员或系统管理员）。`/login`、`/register`、`/forgot-password` 标记 `meta.public`，不参与 token 守卫；已登录用户访问这三页统一跳 `/`。

## 4. 页面规格

### 4.1 登录 `/login`

| 区块 | 内容 |
| --- | --- |
| 左侧品牌（`md+`） | 标题「家庭麻将 · 一桌一世界」、副文案、5 张浮动牌装饰（`size=lg`、opacity 0.13、`scale-2.4`） |
| 右侧登录卡 | `login_id`（手机号/账号）、`passwd`、登录按钮、错误条 |
| 辅助入口 | 「忘记密码」→ `/forgot-password`（常驻）；「注册账号」→ `/register`（仅 `options.register_enabled=true` 时渲染） |
| 底部 | 服务状态点（`/api/health`）+ 版本号 |
| 状态 | 加载中按钮禁用；账号服务不可用显示「账号服务暂时不可用」；失败不区分账号/密码（安全） |
| 已登录 | 带有效 token 访问 `/login` 直接跳 `/`，不回显表单 |
| 移动端 | 只显示登录卡，背景保留渐变 |

### 4.1.1 注册 `/register`

| 区块 | 内容 |
| --- | --- |
| 布局 | 复用登录页两栏：左侧品牌 + 浮动牌装饰；右侧注册卡。窄屏只留卡片 |
| 表单 | `login_id`（手机号）、`verify_code`（右侧「获取验证码」+ 倒计时）、`passwd`（可见切换）、确认密码（仅前端比对）、`nick_name`（可选） |
| 条款 | 勾选框「我已阅读并同意服务条款与隐私政策」；未勾选时提交按钮禁用，点击时提示 |
| 校验 | 手机号 `^1[3-9]\d{9}$`；验证码 `^\d{6}$`；密码 6–32 位；两次一致（规则权威见 [04 §2.1](04-协议设计.md)） |
| 发码 | 按钮在「发送中 / 倒计时中 / 手机号非法」时禁用；成功提示「验证码已发送」，按钮变 `xx 秒后重发`；重发不清空已填内容 |
| 提交 | 成功 toast「注册成功，请登录」→ 1.5s 后跳 `/login` 并预填手机号；失败保留输入，仅清空验证码 |
| 关闭态 | `register_enabled=false`：整页「注册未开放，请联系管理员开通账号」+ 返回登录；不渲染表单，也不发请求 |
| 错误 | 已注册：字段下方红字「这个账号已经注册过了」+「去登录」；验证码错：清空并高亮；发送过频：按钮显示剩余冷却秒数 |
| 移动端 | 单列；验证码按钮与输入框同行且不被压缩；键盘弹起时提交按钮仍可见 |

### 4.1.2 找回密码 `/forgot-password`

| 区块 | 内容 |
| --- | --- |
| 布局 | 同登录页单卡；顶部两步指示器「1 验证账号 → 2 设置新密码」 |
| 第一步 | 手机号 + 「获取验证码」（60s 倒计时）；发送成功即进入第二步。统一提示「若该手机号已注册，验证码已发送」，不暴露账号是否存在 |
| 第二步 | 脱敏手机号（`138****0000`）+「重新发送」；`verify_code`、新密码、确认新密码；「返回上一步」保留手机号 |
| 校验 | 验证码 `^\d{6}$`；新密码 6–32 且两次一致（规则权威见 [04 §2.2](04-协议设计.md)） |
| 提交 | 成功 toast「密码已重置，请用新密码登录」→ 1.5s 后跳 `/login` 并预填手机号；失败只清空验证码，保留手机号与已填的新密码 |
| 错误 | 验证码错/过期：「验证码不正确或已失效」；连续 5 次：「验证码错误次数过多，请重新获取」并禁用提交；新旧口令相同：「新密码不能和原密码一样」 |
| 关闭态 | `password_reset_enabled=false`：显示「自助找回已关闭，请联系管理员重置」+ 返回登录 |
| 安全 | 失败文案不区分「手机号未注册 / 验证码错误」；页面不回显任何历史口令 |

### 4.2 家庭 `/families`

- 顶部「我的家庭」卡片网格：家庭名、角色徽标（owner/admin/member）、成员数、默认规则族/皮肤、进入按钮。
- 「创建家庭」卡：名称输入 + 编码（可自动生成）+ 默认规则族下拉。
- 空状态：插画 + 「先创建一个家庭，再邀请家人」。
- 无加入入口：成员由家庭管理员按 `login_id` 添加（与账号体系一致）。

### 4.3 大厅 `/`

| 区块 | 说明 |
| --- | --- |
| 统计条 | 累计积分、场次、胡牌局数（按当前家庭） |
| 我的牌桌 | 卡片：房间名、邀请码（等宽数字）、规则名、人数（`2/4`）、状态；点击进入 |
| 邀请码入房 | 6 个数字格，输入即跳格、退格回退、填满自动查询；仅数字键盘；错误提示在格下方 |
| 快速入口 | 规则模板、战绩、皮肤（管理员） |
| 创建牌桌 | 弹窗：房间名、规则族（tab）→ 模板（卡片，显示族与摘要）→ **打几圈**（`1/2/4/8`，默认 4 圈，随模板 `circles_per_game` 联动，点选后不再被模板覆盖；每档附「约 N 局」）→ 创建；摘要条显示「每圈 4 个庄次，本桌 N 圈（计划 M 局）」；无可用模板时引导去规则页 |
| 空状态 | 「还没有牌桌，开一桌吧」+ 主按钮 |
| 满座 | 提示「牌桌已满，可旁观 4 位玩家之一」；`spectate.available=false` 时提示「围观人数已满」并禁用进入 |

### 4.4 规则 `/rules`

- 左栏：规则族下拉/标签（通用、柏氏、广东、四川）+ 模板列表（预置带「预置」金色角标，家庭模板带创建者）。
- 右栏：
  - 头部：模板名（可编辑）、说明、族徽标、状态。
  - 预览条：一句话摘要 + 算分示例。
  - 表单：按 `capability` 动态渲染；不支持的开关不显示；关闭的开关折叠从属项。
  - 番表：可增删行，`id` 只读、`name/fan/exclusive_group/stackable` 可编辑；行内校验红框。
  - 底栏：保存、另存为副本、停用。
- 预置模板：整表单 `disabled` + 琥珀提示「预置模板只读，复制后可改」。
- 柏氏模板：若 `ready=false`（引擎未通过 07 验收），显示「引擎未就绪」并禁用保存/开桌入口。

| 状态 | 表现 |
| --- | --- |
| 等待 | 四座牌背 + 「准备/开始」按钮；满座时显示观战入口；房主可见开始条件（人数/准备） |

| 抽座 | **每场首局**开始前：四座依次弹出骰子点数并显示「<昵称> · 9 点」；确定后给庄家加「庄」金框，座位角标显示**本局门风**（庄家恒为「东」，逐局转动）；系统播报「东风局开始，本局庄家：<昵称>」 |
| 进行中 | 当前座位 `breathe` 光环；倒计时环（≤5s 变朱红）；可操作按钮仅高亮合法项；**ScoreBoard 显示「东风局 · 第 2/4 圈 · 第 3/4 局」与庄家昵称**（单圈房只显示局数；连庄时追加「（连庄）」）；座位角标显示围观人数（>0 时「围观 3」，不含观战者身份） |
| 询问窗口 | 顶部横幅「有人打出 X，可以碰/吃/胡」+ 倒计时；`ActionBar` 显示候选。抢杠窗口（仅明杠）文案「<昵称> 明杠 X，可抢杠胡」，只给能胡该张的座位显示「抢杠胡」按钮 |
| 询问·胡优先（v1.1.0） | 本张牌可胡时 `ActionBar` **只保留「胡」「不胡」**（服务端本就只下发 `hu/pass`）；点「不胡」= 过胡（仅本张牌），同一窗口随即补出「碰/杠/吃/过」；第二阶段文案用「过」，避免与「不胡」混淆。禁止把「吃/碰」与「胡」并列抢点击 |
| 吃牌选牌（v1.1.0） | 点「吃」不直接提交，进入 `chow-select`：动作条收起，原位展开两行面板（第一行「来牌 + 已选/提示 + 候选」，第二行「确认吃 / 取消 / 过」；宽度 `min(94vw,680px)`，仍在动作条槽位内，手牌不被遮挡，牌河最多被压住下沿）；**默认高亮推荐组合**（服务端 `chow.tiles` 第一组）；可在手牌上点选两张（再点取消，选满再点第三张挤掉最早一张），或点候选一键套用；两张合法才可「确认吃」，不合法时按钮置灰并提示「这两张不能和被吃的牌组成顺子」/「再点 1 张手牌」；「取消」只退出选牌态（回到动作条，可再次进入），放弃本次吃牌需点「过」；超时由服务端按过收口、前端自动退出选牌态。桌面与手机横屏同一套组件，手机底部操作槽变高时只压缩牌河、不动手牌。例：手牌 `234556 万`、来 `4 万` → 可选 `234 / 345 / 456` |
| 已暂停 | 顶部半透明横幅「已暂停 · 由 <昵称> 暂停」；手牌与牌河置灰，`ActionBar` 只保留「恢复」；无倒计时、不掉线、不接受他人操作 |
| 结算 | `ResultModal`：番数大字（累计值，例「40 番」）、番种 chips（按番值降序，同组只出现一个；风刻显示「门风刻 1」「圈风刻 1」）、倍数角标（「自摸 ×2」「庄家 ×2」，可叠加显示 ×4）、包牌提示条（「<昵称> 包三家」+ 独付金额）、四家分差与付款方明细、本人输赢；「下一局」/「查看总账」 |

## 6. 牌面皮肤规格

### 6.1 资源键 `tile_key`（34 张牌 + 牌背 = 35 个必填；`preview` 可选且不计入 `tile_key`）

| 分组 | 键 | 数量 |
| --- | --- | --- |
| 万 | `1m` … `9m` | 9 |
| 筒 | `1p` … `9p` | 9 |
| 条 | `1s` … `9s` | 9 |
| 字牌 | `east`、`south`、`west`、`north`、`red`、`green`、`white` | 7 |
| 牌背 | `back` | 1 |
| 预览（可选，**不是 `tile_key`**） | `preview` | 1 |

- 键名大小写敏感，只用小写；文件扩展名 `.png` / `.webp`。
- 前端 `tileKey(tile)` 映射：`0–8 → 1m–9m`、`9–17 → 1p–9p`、`18–26 → 1s–9s`、`27–33 → east…white`。

### 6.2 图片规格

| 项 | 规格 |
| --- | --- |
| 画布 | `192 × 288`（2×），逻辑尺寸 `96 × 144` |
| 宽高比 | `2:3`（`tile_aspect = 0.6667`） |
| 格式 | PNG（透明）或 WebP（有损 ≤ 85 / 无损） |
| 背景 | 透明；牌面本体铺满画布，圆角约 `12px`（2× 下） |
| 阴影 | **不画阴影**，由 CSS `shadow-tile` 提供，避免与选中位移冲突 |
| 安全边距 | 内边距 `6px`（2×），文字/图案不触边 |
| 单文件 | ≤ 512 KB |
| 命名 | 服务端生成 `{tile_key}.{hash8}.{ext}`，用户文件名不落盘 |
| 预览图 | `480 × 320`，展示一张手牌 + 牌背，≤ 800 KB |

### 6.3 状态与渲染

| 状态 | 渲染 |
| --- | --- |
| 正常 | `<img>` 铺满容器，`object-fit: contain`；无图片时回退 CSS |
| 选中 | 容器 `translateY(-8px)` + `shadow-gold`；图片不缩放 |
| 高亮 | `ring-1 ring-gold-400/70`，用于最后一张出牌/听牌提示 |
| 变暗 | `opacity-45`，用于不可用/弃牌 |
| 牌背 | `tile_key=back`；无图时回退深绿渐变 + 金边 |
| 缺图 | 单张 `onerror` → 该张回退 CSS；不弹错误、不阻塞牌桌 |
| 加载 | `loading="lazy"`、`decoding="async"`；首屏手牌 `eager` |
| 缓存 | `/majiangapp/tiles/**` 带 `Cache-Control: public, max-age=31536000, immutable`；文件名含内容哈希 |

### 6.4 皮肤清单契约

```json
{
  "skin_code": "lianjia-jade",
  "skin_name": "廉家青玉",
  "family_code": "lianjia",
  "is_default": true,
  "tile_aspect": 0.6667,
  "asset_count": 35,
  "assets": {"1m":"/majiangapp/tiles/lianjia-jade/1m.8f3a1c.webp","back":"/majiangapp/tiles/lianjia-jade/back.2b9d40.webp"},
  "fallback": "css-classic",
  "updated_at": "2026-10-25T19:30:00+08:00"
```

- 前端一次性拉取当前家庭可用皮肤，内存缓存；切换只换 `assetMap`，不重新拉清单。

- `fallback` 固定 `css-classic`，用于整皮肤不可用时的最终兜底。

## 7. 响应式与适配

| 断点 | 布局 |
| --- | --- |
| `<640px` | 单列；手牌横向滚动；按钮全宽；家庭/规则卡片单列 |
| `640–1023px` | 大厅/规则两列降为单列；牌桌仍为三方布局但缩小侧栏 |
| `1024–1279px` | 牌桌完整布局；聊天固定右栏 |
| `≥1280px` | 内容最大宽 1400px，牌桌居中 |

硬约束：

- 手牌任何断点不得缩小到 `<32px` 宽（可滚动，不压缩）。
- 操作栏与手牌不重叠；安全区 `env(safe-area-inset-bottom)`。
- 移动端不显示悬停提示信息；所有关键信息有常驻文案。

## 8. 可访问性

- 文本对比度 ≥ 4.5:1（米色牌面上的深墨绿、金色按钮上的深色字）。
- 所有交互元素可键盘聚焦，`focus-visible` 金色描边；牌可用方向键 + Enter 选中/出牌。
- 颜色不作为唯一信息：准备/断线/听牌同时有图标或文字。
- 动效尊重 `prefers-reduced-motion`。
- 图片 `alt` 为牌名（「五万」「红中」）；装饰图 `alt=""`。

## 9. 验收清单

1. 5 个既有页面视觉不回退，新增家庭/皮肤/成员页风格一致。

5. 键盘可完成登录、选家庭、开桌、出牌。
