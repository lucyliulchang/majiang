## 2. 字段与命名规范

### 2.1 通用规范

| 项 | 规范 |
| --- | --- |
| 主键 | 首列固定 `recID INT AUTO_INCREMENT PRIMARY KEY COMMENT '记录ID'` |
| 业务唯一键 | 单列内联 `UNIQUE`。组合键由应用层拼接后存单列，命名 `xxxKey`（如 `gameSeatKey`/`familyMemberKey`/`skinTileKey`）；自然业务码（`familyCode`/`roomCode`/`templateCode`/`skinCode`/`ruleFamilyCode`）直接内联 `UNIQUE`，不加 `Key` 后缀 |
| 时间 | `VARCHAR(16)`，格式 `YYYYMMDDHHMMSS`（Asia/Shanghai），字段名以 `YMDHMS` 结尾；读写一律走 `common/miscCommon.py` 的时间函数族（`getTime`/`addTime`/`diffTime` 等），实现规范见 [docs/开发指南.md §3](../docs/开发指南.md) |
| 布尔 | `CHAR(1)`，`'1'`/`'0'`，字段名以 `Flag` 结尾 |
| 状态 | `VARCHAR(16)` 或 `VARCHAR(24)`，全大写枚举，字段名以 `Status` 结尾 |
| 金额/分 | `INT`，单位「分」，允许负值 |
| 文本 | 短文本 `VARCHAR(n)`，长文本 `TEXT`/`MEDIUMTEXT`；单行不超过 500 字优先 `VARCHAR(500)` |
| 外键 | **不建数据库外键**；关系由应用层保证；关联列命名 `xxxID` 或 `xxxCode` |
| 软删 | 尾部 `delFlag CHAR(1) NOT NULL DEFAULT '0'`；业务只查 `delFlag='0'` |
| 审计尾列 | `label`、`memo`、`regID`、`regYMDHMS`、`modifyID`、`modifyYMDHMS`、`delFlag` 顺序固定 |

### 2.2 生成器硬约束（必须遵守）

1. 一行一个字段；**单空格**分隔，禁止 Tab。
2. `COMMENT` 内禁止 `%`（会被替换为全角）与 `#`（会被当注释截断）。
3. 首字段固定 `recID INT AUTO_INCREMENT PRIMARY KEY`；尾部七字段顺序不可变。
4. 不支持复合唯一键、外键、分区、`CHECK`；唯一性用「应用层拼接单列 + 内联 UNIQUE」。
5. 类型白名单：`INT/BIGINT/SMALLINT/TINYINT/DECIMAL/FLOAT/DOUBLE/VARCHAR/CHAR/TEXT/MEDIUMTEXT/LONGTEXT/JSON/DATE/DATETIME/TIMESTAMP`。`JSON` 可建列，但需在 `mysqlCommon` 登记归一化。
6. 执行目录必须是 `database/`，且只传裸文件名：`python mysqlCodeGenerator.py -i mj_room.txt -t room`。
7. `-t` 取「去 `mj_` 前缀 + 去全部下划线」：`mj_game_player` → `gameplayer`。
8. 产物在 Windows 下可能是 GBK；合并工具按 `utf-8 → gbk` 容错解码后统一 UTF-8 写回。
9. 生成版 `query_*` 的 `LIMIT` 拼装被注释掉，**不直接使用**；列表查询在 `mysqlCommon` 手写区实现。
10. `auto_generated/` 禁止手改，重跑即覆盖。

```
finalHandsJson JSON NULL COMMENT '终局四家手牌与副露 含胡张 用于结算回放核对'
finishedYMDHMS VARCHAR(16) NOT NULL COMMENT '结算时间'

memo VARCHAR(200) COMMENT 'memo'
regID VARCHAR(32) COMMENT '注册ID'
regYMDHMS VARCHAR(16) COMMENT '注册年月日'
modifyID VARCHAR(32) COMMENT '修改用户ID'
modifyYMDHMS VARCHAR(16) COMMENT '修改年月日'
delFlag CHAR(1) NOT NULL DEFAULT '0' COMMENT '删除标记'
```

落库约定（座位/轮庄/荒庄，语义见 03 §3.4–3.6）：

- `seatDrawJson` 只在每圈抽座后写一次，形如 `{"assignments":[{"seat":0,"loginID":"138...","dice":[3,4]}],"dealerSeat":0,"capturedYMDHMS":"20261026193000"}`。
- **荒庄（有杠）**记一行：`winnerSeat=NULL`、`winType='none'`、`roundWind` 为本局局风、`scoreDeltaJson` 仅含已结算杠分。
- **无杠重发**不落库（局号不变、无结算），只在 `mj_room_message` 留一条 system 播报。
- `dealerSeat` 恒等于 `roundNo-1`（一轮 4 局内），冗余存储用于历史直读与核对。
- `finalHandsJson` 记录**终局四家的手牌与副露**（点炮/抢杠的胡张已并入赢家手牌），供战绩页回放核对番种：
  `[{"seat":0,"login_id":"138...","display_name":"刘畅","concealed":[18,19,25,...],"melds":[{"kind":"pong","kind_name":"碰","tiles":[31,31,31],"from_seat":2,"claim_tile":31}],"is_winner":true,"win_type":"discard","winning_tile":25}]`。
  牌用 0–33 编码（04 §9.3）；暗杠也按真实牌面存（战绩详情只对本家成员开放）。旧局该列为 `NULL`，前端按空数组处理。

## 5. JSON 列登记

`common/mysqlCommon.py` 必须维护：

```python
MYSQL_JSON_COLUMN_NAME_LIST = [
    "capabilityJson",   # mj_rule_family
    "configJson",       # mj_rule_template
    "ruleSnapshot",     # mj_room / mj_game

    "scoreDeltaJson",   # mj_game_round
    "payerJson",        # mj_game_round
    "finalHandsJson",   # mj_game_round
    "detailJson",       # mj_audit_log
]
```

写库统一 `normalizeJsonValue4DB(value)`：

- `dict/list` → `json.dumps(..., ensure_ascii=False, separators=(",", ":"))`
- `None` / `""` → `None`
- 其它 → 原样（由 MySQL 报错暴露问题，不静默转字符串）

读取统一 `misc.jsonLoads` 容错：解析失败返回 `{}` / `[]` 并记 `warning`，不使整个接口 500。

批量脚本 `tools/genTableCode.ps1` 必须：

1. `Set-Location` 到 `database/`；
2. 遍历 `mj_*.txt`（**不包含** `userBasic.txt`）；
3. `$title = ($tableName -replace "^mj_", "") -replace "_", ""`；
4. 单表失败即记录并最终 `exit 1`。

### 6.2 合并

```powershell
cd code/backend
python tools/mergeMysqlCommon.py
```

工具职责：抽取产物 `#mysqlCommon code begin/end` 段 → 写入 `common/mysqlCommon.py` 的 `#===== auto-generated sections begin/end` → 校验每表 7 个函数齐全（`tablename_convertor_/decode_/create_/drop_/delete_/insert_/update_`）→ 丢弃生成版 `query_*`。手写区不被覆盖。

### 6.3 建表

```powershell
cd code/backend
python tools/initTables.py --env local            # 建库+建表+索引
python tools/initTables.py --env local --seed     # 追加规则族/预置模板/内置皮肤
```

红线：

- 只 `CREATE TABLE IF NOT EXISTS` 与 `CREATE INDEX`，**禁止 `DROP`**。
- 生产改表走「备份 → 测试库演练 → 保留回滚 DDL」，不做自动迁移。
- 每次结构变更追加一条 `mj_schema_version`。

## 8. 常见查询（手写区）

| 场景 | 函数 | 关键条件 |
| --- | --- | --- |
| 按邀请码取房 | `query_mj_room_by_code(roomCode)` | `delFlag='0'` |
| 我的家庭 | `query_mj_family_list_by_login(loginID)` | join `mj_family_member`，`memberStatus='ACTIVE'` |
| 家庭房间 | `query_mj_room_list(familyID, limit, beforeID)` | `roomStatus='OPEN'`，倒序 |
| 模板列表 | `query_mj_rule_template_list(familyID, ruleFamilyCode)` | `familyID IN (0, ?)`，`activeFlag='1'` |
| 皮肤清单 | `query_mj_tile_skin_list(familyID)` | `familyID IN (0, ?)`，`skinStatus='ENABLED'` |
| 皮肤资源 | `query_mj_tile_skin_asset_list(skinID)` | `delFlag='0'` |
| 最近聊天 | `query_mj_room_message_list(roomID, limit)` | `ORDER BY recID DESC LIMIT ?` |
| 场次列表 | `query_mj_game_list(familyID, loginID, limit, beforeID)` | 参与者子查询 |
| 场次详情 | `query_mj_game_detail(gameID)` | game + players + rounds |
| 更新总分 | `update_mj_game_player_score(gameID, seatNo, delta)` | `SET totalScore = totalScore + ?` |
| 软删 | `delete_mj_xxx(tableName, recID)` | `SET delFlag='1', modifyYMDHMS=?...` |

分页统一 `recID < beforeID ORDER BY recID DESC LIMIT ?`，避免 `OFFSET` 深翻页；`limit` 默认 20、最大 100（战绩/审计默认 30），与 [04 §1](04-协议设计.md) 一致。

## 9. 备份与恢复要点

- 全量：`mysqldump --single-transaction --routines --triggers --default-character-set=utf8mb4 mahjong_data > mahjong-YYYYmmdd-HHMMSS.sql`。
- 增量：binlog（`log_bin=ON`，保留 7 天）。
- 恢复：新建空库 → 导入全量 → `mysqlbinlog` 回放 → 校验 `mj_schema_version` 最后版本与 `SELECT COUNT(*)` 关键表。
- 上传文件单独备份 `UPLOAD_DIR`（生产 `/data/webserver/majiangapp`），与 DB 备份同一批次。
