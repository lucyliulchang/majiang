# 03 · 规则族设计

> 状态：已评审（2026-10-27）
> 上游：[02-数据库设计.md](02-数据库设计.md)（表 `mj_rule_family`、`mj_rule_template`）
> 本文是**规则语义的唯一权威**；协议只引用字段名，不重复解释规则。

## 1. 三层模型

| 层 | 载体 | 可变性 | 说明 |
| --- | --- | --- | --- |
| 规则族 | `mj_rule_family` + `game/families/{engineCode}/` | 发版级 | 决定引擎插件、牌张集合、可用开关、结算能力 |
| 规则模板 | `mj_rule_template.configJson` | 用户可编辑 | 族内参数预设，归属家庭（`familyID=0` 为全局预置） |
| 规则快照 | `mj_room.ruleSnapshot` / `mj_game.ruleSnapshot` | **不可变** | 开桌/开局时冻结「族 + 模板 + 生效配置」，历史可复现 |

开桌只选模板（`template_id`），服务端读取模板 → 校验族 → 合并默认值 → 生成快照；**客户端不能直接提交快照**。

### 2.2 能力声明 `capabilityJson`

```json
{
  "tile_set": "136",
  "allow_chow": true,
  "honors": true,
  "wind_fan": true,
  "patterns": ["standard", "seven_pairs", "thirteen_orphans", "thirteen_unrelated"],
  "fan_combine": ["group_best"],
  "fan_modes": ["linear", "exponential"],
  "fan_cap_allowed": true,
  "fan_cap_max": 30,
  "switches": ["turn_timeout", "kong_score", "ting_hint", "draw_penalty"],
  "settlement": ["self_draw", "discard", "draw", "kong", "rob_kong"],
  "multi_winner": false,
  "bao_pai": false,
  "self_draw_multiplier": 1,
  "dealer_multiplier": {"win": 1, "pay": 1},
  "lack_suit": false,
  "min_fan_to_win": 0,
  "max_rounds": 4
}
```

字段含义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `tile_set` | `"136"`/`"108"` | 牌张集合；108 = 万筒条各 36，无字牌 |
| `allow_chow` | bool | 模板是否允许 `allow_chow=true` |
| `honors` | bool | 是否含字牌（决定十三幺等牌型是否可用） |
| `wind_fan` | bool | 是否计风刻番（门风刻 / 圈风刻）；无字牌族为 `false` |
| `patterns` | string[] | 该族支持的牌型插件 id |
| `fan_combine` | string[] | 番种合成方式：`group_best`（同组取最高，通用族）/ `sum_all`（除同组互斥外全部累加，柏氏） |
| `fan_modes` | string[] | 支持的折算方式：`linear`（底分×番）/ `exponential`（底分×2^番） |
| `fan_cap_allowed` | bool | 是否允许模板配置封顶；柏氏为 `false`（不封顶） |
| `fan_cap_max` | int | 封顶番数上界；通用族 `30`，柏氏 `0`；0 且 `fan_cap_allowed=false` 表示族级禁用封顶 |
| `switches` | string[] | 该族可用的可选开关；不在列表中的开关模板禁止开启 |
| `settlement` | string[] | 结算能力；`bao_pai` 等扩展结算在此登记。`rob_kong` 的**可抢范围由族定义**：柏氏为「仅明杠」（补杠、暗杠不可抢） |
| `multi_winner` | bool | 是否支持一局多胡（血战到底） |
| `bao_pai` | bool \| object | 是否支持包牌；对象形式 `{supported, win_type, min_exposed_melds, patterns, payer}` 见 §7.2 |
| `self_draw_multiplier` | int | 自摸时所有付款方的倍率；通用/广东/四川为 1，柏氏为 2 |
| `dealer_multiplier` | object | `{win, pay}`：庄家胡时全体付款方倍率、庄家作为付款方时倍率；通用族均为 1 |
| `lack_suit` | bool | 是否强制缺一门 |
| `min_fan_to_win` | int | 起胡番数 |
| `max_rounds` | int | 一圈局数；四族固定 `4`（北位庄家下庄即圈结束，见 §3.4），不可配 |

约束：`capabilityJson` 只增不改语义；新增字段必须有默认值，旧模板仍可解析。

### 3.2 接口（Protocol）

```python
class RuleEngine(Protocol):
    family_code: str
    tile_set: tuple[int, ...]

    def start_round(self, dealer_seat: int, round_wind: int) -> list[dict]: ...
    def legal_actions(self, seat: int) -> dict: ...
    def apply_action(self, seat: int, action: dict) -> list[dict]: ...
    def timeout_claim(self) -> list[dict]: ...
    def tenpai_map(self, seat: int) -> dict[int, list[int]]: ...
    def settlement(self) -> "RoundSettlement": ...
    def next_dealer(self, settlement: "RoundSettlement") -> int: ...
    def snapshot_options(self) -> dict: ...
    @property
    def remaining(self) -> int: ...
```

`RoundSettlement`（统一结构，兼容单赢家与多赢家）：

```python
{
  "round_no": 1,
  "dealer_seat": 0,
  "winners": [                      # 单赢家时长度 1；荒庄为空
    {"seat": 2, "win_type": "self_draw",   # self_draw | discard | rob_kong
     "winning_tile": 15,
     "pattern_id": "standard", "fan_items": [...],
     "fan_raw": 41, "fan_cap": None, "fan_total": 41,   # 封顶前 / 封顶值 / 封顶后
     "multipliers": {"self_draw": 2, "dealer": 1},      # 生效倍率
     "score_from_fan": 328, "breakdown": {...}}
  ],
  "score_delta": [0, -164, 328, -164],  # 座位 0..3，恒满足 sum==0
  "payer_allocation": [                 # 可选；包牌族使用
    {"winner_seat": 2, "reason": "bao_pai", "bao_pai_seat": 0,
     "covered": [1, 3], "payers": [{"seat": 0, "amount": -328}]}
  ],
  "kong_delta": [0, 3, 0, 0],           # 杠分即时结算，已并入 score_delta
  "summary": "二筒自摸，清一色 30 + 对对胡 10",
  "is_draw": false
}
```

适配约定：`generic` 可直接把现有 `SettledRound` 映射为单元素 `winners`（`fan_raw == fan_total`、倍率全 1）；`sichuan` 返回多元素；`baishi` 通过 `payer_allocation` 重分配付款方，**不修改 `score_delta` 的合计守恒**，`fan_total` 为番合计（累计，不乘积）。

落库映射：`fan_raw → mj_game_round.fanRaw`、`fan_total → fanTotal`、`winners[0].fan_items → fanItemsJson`、`payer_allocation[0] → payerJson`、`score_delta → scoreDeltaJson`。

### 3.3 状态机

`waiting → dealing → discard → claim → discard … → settled`。族可扩展内部阶段（如四川的「血战继续」用 `settled` + `winners` 非空 + `remaining_players` 表示），但**对外事件类型不变**，避免前端分叉。

### 3.4 座位、庄家与局风

四族**完全一致**，与模板/族能力无关；实现落在通用骨架 `game/engine.py` 与 `realtime/room.py`。

| 项 | 规则 |
| --- | --- |
| 座位方位 | 座位号 `0/1/2/3` 是**物理座位**（抽座时以 东/南/西/北 签命名，座位 0 = 东位）；摸牌、出牌、询问窗口、轮庄顺序恒为 `0→1→2→3` |
| 抽座时机 | 每**圈**开始前抽座一次（一场首局即第一圈），**圈内 4 局座位不变**；不是每局重抽 |
| 抽座方式 | ① 四人各抽一张风签（东南西北各一张）定物理座位；② 四人依次各掷 **2 颗骰子**，点数和最大者坐 `座位 0`（东位）并坐庄，若其抽到的不是东位则与东位玩家**交换座位**；③ 同点按**先掷者优先**（「先为东」）；仍并列最高则并列者重掷到唯一最大 |
| 首次抽座 | 每圈首局触发（含开桌后第一局，需 4 人全部准备），抽座结果广播 `event.seats_drawn`（见 04 §9.4） |
| 庄家轮转 | **每局换庄**：第 `n` 局（`n = 1..4`）庄家 = 座位 `(n-1)`；**不设连庄**，也不按「谁胡牌谁坐庄」 |
| 门风（座风） | 门风 = `(座位号 - 庄家座位) % 4`：**庄家恒为东风**，其下家南风、对家西风、上家北风；每局随轮庄整体转动 |
| 局风 | 局风 = **局序**，与谁是庄家无关：第 1 局东风、第 2 局南风、第 3 局西风、第 4 局北风；每场从东风局重新起算 |
| 场与圈 | 一场 = 一圈：庄家按 `0→1→2→3` 轮转，**座位 3（北位）庄家打完下庄即该圈结束**；因此一圈**最少 4 局**（每个座位各坐庄一次）。无杠重发在同一局内，只增加实际发牌手数、不增加局数。房间内可连续开多场，每场重新抽座 |

> 两个「风」不要混：**门风**看庄家（庄家=东，逐局转动），**局风**看局序（第 1 局=东，与庄家无关）。风刻番分别对应两者（07 §6.9）。

推论：`next_dealer()` 恒返回 `(dealer_seat + 1) % 4`（**重发**除外，见 §3.6）；`dealer_continue_on_win/draw` 两个配置项作废，模板中不再接受。

### 3.5 发牌与开牌

| 步骤 | 规则 |
| --- | --- |
| 洗牌 | 服务端 Fisher-Yates 洗满整副牌（136/108）；`deal_seed` 记入服务端日志（便于复现排查），不下发客户端 |
| 定开牌点 | 庄家掷 2 颗骰子得点数和 `S`（2–12）：从庄家起按 `0→1→2→3` 数 `S` 家（庄家算第 1 家）得**开牌家**；再从开牌家牌墙**右端**数 `S` 墩，其后一墩为**开牌点**。牌墙视为首尾相接，自开牌点按座位顺序续接成取牌序列；序列**尾部**为杠后补牌端与海底判定端 |
| 发牌 | 每轮每人 **4 张（2 墩）**，从庄家起按座位序（庄家→下家→对家→上家，即门风 东→南→西→北）依次；共发 **3 轮**，每人 12 张 |
| 跳牌 | 庄家取取牌序列的**第 1、第 5 张**；下家、对家、上家依次各取 1 张（即第 2、3、4 张，门风 南/西/北）。结果：庄家 **14** 张、闲家各 **13** 张，无剩余牌悬空 |
| 首轮 | 庄家不摸牌，直接出牌；此后按 `0→1→2→3` 摸一张打一张 |
| 补牌 | 杠后补牌从取牌序列**尾部**取（与 07 §6.5.2 海底判定同一端口径） |
| 牌墙耗尽 | 取牌序列取尽（含尾部补牌）即触发 §3.6 判定 |

骰子与开牌点属**可复现要求**：`event.round_started.deal` 下发 `{dice:[d1,d2], break_seat, break_stack}`，前端仅用于展示，重连以快照为准。

### 3.6 荒庄

触发条件：**取走最后一张牌之后仍无人胡**（牌墙取尽）。按本局是否发生杠分成两种结局，语义不同，落库也不同：

| 分支 | 条件 | 处理 |
| --- | --- | --- |
| 荒庄 | 本局发生过杠（**明杠、暗杠、补杠均算**，见下） | 记为一局：`winner_seat=null`、`is_draw=true`；已即时结算的杠分**保留不回滚**、**不罚分**；庄家迁到下一座位，局号 +1、局风 +1，本局推进轮庄 |
| 重发 | 本局未发生任何杠 | 本局作废，**不落库**：座位、庄家、局风、局号全部不变；重新洗牌并发同一局；广播 `event.round_restarted`，重发次数不限 |

约定：

- **三类杠都算「发生过杠」**：明杠（大明杠：别人打出第 4 张时杠）、暗杠（自己手里 4 张扣下）、补杠（碰出明刻后又摸到第 4 张，加到原刻子上成杠；属明杠类，可被抢杠胡）。
- 荒庄**没有赢家、没有输家**，`score_delta` 只含已发生的杠分（无杠时为全 0）。
- 「迁移庄家」= 按座位序把庄家交给下家（`(dealer_seat+1)%4`）。
- 圈结束只看庄家轮次：**座位 3（北位）庄家这一局结算完成（含荒庄），本圈结束**，下一圈重新抽座。若北位这局是「无杠重发」，则该局尚未结算，圈未结束，继续重发同一局。
- 通用族的 `draw_penalty` 仅在**荒庄（有杠）**分支生效；`重发` 分支恒不罚分。柏氏族 `draw_penalty` 恒 0（07 §9）。
- 海底捞月（柏氏）在「最后一张为 1 筒且摸者自摸胡」时先判胡，胡成立则不是荒庄。

求值流程：牌型插件产出 `fan_hits` → 按 `exclusive_group` 取最高 → 展开可叠加项 → 汇总 `fan_raw` → 按 `fan_cap` 截断 → 按 `fan_mode` 折算。

### 4.3 牌型开关

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `standard` | true | 4 面子 + 1 将；递归拆解，多解取最高番 |
| `seven_pairs` | true | 七对（含龙七对） |
| `thirteen_orphans` | true | 十三幺 |
| `thirteen_unrelated` | `{enabled:false, require_all_honors:false, allow_pair:true, min_gap:3}` | 十三不靠；`min_gap` 2–9 |

### 4.4 结算

- `linear`：`base_score × max(1, fan_total)`；`exponential`：`base_score × 2^min(fan_total, 20)`。
- 自摸三家各付；点炮按 `discard_pay_mode`（`single` 独付 / `all` 三家分摊）。
- 杠分：明杠由放杠者付、暗杠/补杠三家各付；`kong_score.enabled=false` 时仍可杠，分全 0。
- 荒庄：仅「荒庄（有杠）」分支结算（§3.6）；`draw_penalty.enabled` 时三家罚 `value` 给庄家，否则 0。「无杠重发」不结算、不罚分。
- 风刻：`men_feng` = 胡牌者**门风**（§3.4，庄家恒东）的刻子/杠，`quan_feng` = **局风**（局序）的刻子/杠；各 1 番，可同时命中（+2），判定口径与柏氏 07 §6.9 一致。
- 抢杠胡：通用族复用点炮结算，付款方为被抢杠者；柏氏口径不同（三家各付、不乘自摸倍数、不触发包牌），以 07 §3.3/§6.5.4 为准。

## 12. 验收清单

1. 4 个族的 `capabilityJson` 均能通过 JSON 解析与 schema 校验；`patterns` 全部已在注册表。
2. `generic` 平移后现有 76 个用例全绿（番种、牌型、开关、结算、流程）。
3. `guangdong` 建墙 136 张、`sichuan` 建墙 108 张；四川出牌无字牌、吃牌被拒。
4. 四川一局出现 2 个赢家时 `winners` 长度 2、`sum(score_delta)==0`。
5. `baishi` 引擎验收前开桌返回 `RULE_FAMILY_NOT_READY`；验收后正常开桌，族与模板列表接口始终可用。
6. 同一模板在开桌后修改，进行中场次的快照与结算不变。
7. 关闭 `kong_score` 后杠仍可进行且分差为 0；关闭 `ting_hint` 后快照无 `tenpai`。
8. `baishi` 累计求番：对对胡 + 清一色 → `fan_total=50`（不是 600），`fan_raw == fan_total`（不封顶）。
9. `baishi` 倍数：庄家自摸 `U×4`、闲家自摸 庄家 `U×4` 其余 `U×2`、闲家点炮 庄家 `U×2` 其余 `U×1`。
10. `baishi` 包牌：点炮 + 3 明牌 + 清一色 → 点炮者独付三家合计，另两家 0，`Σ score_delta == 0`；自摸同牌型不包。
11. `baishi` 结算落库后 `payerJson` 可还原包牌者、被包家、金额；`winType=rob_kong` 可落库。
12. 发牌：庄家 14 张、三家各 13 张；抓牌为 4 张 × 3 轮 + 跳牌（第 1、第 5 张），首轮庄家直接出牌不摸牌。
13. 抽座：每圈开始抽一次；圈内 4 局座位不变；第 n 局庄家恒为座位 n-1，门风随之转动、局风按局序 东南西北；座位 3（北位）庄家下庄即圈结束（无杠重发不推进局号）。
14. 荒庄二分：有杠荒庄 → 落库 `winnerSeat=null`、`is_draw=true`、杠分保留、局号+1、庄家迁下家；无杠重发 → 不落库、局号/庄家/局风不变、广播 `event.round_restarted`。
15. 风刻：第 1 局（局风东）、庄家（门风东）胡且持东刻子 → `fan_total` 额外 +2；第 2 局起庄家持东刻子只计门风刻 1 番。
